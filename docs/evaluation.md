# 평가

05는 04가 만든 답변 파일 하나를 검색 · 답변 · 근거 · 최종의 네 가지로 채점합니다. 요약은 README의 [평가](../README.md#평가)에 있습니다.
이 문서에는 검색 지표를 계산하는 방법, 검색만 다시 돌리는 방법, 최종 test 평가 순서, 평가 자료를 되살리는 방법, 정답 근거를 청크에 연결하는 규칙이 있습니다.

## 검색 지표 계산

### 순위 지표

답변 모델에 넘기기 전(비슷한 내용 빼기와 토큰 한도 적용 전)의 후보 목록으로 계산합니다. k는 5, 10, 20입니다.

| 수준 | Recall@k | MRR@k |
| --- | --- | --- |
| 문서 | 상위 k개 조각에 나온 정답 문서 수 ÷ 전체 정답 문서 수 | 정답 문서의 조각이 처음 나온 순위의 역수 |
| 청크 | 상위 k개에 든 정답 청크 수 ÷ 전체 정답 청크 수 | 정답 청크가 처음 나온 순위의 역수 |

- k 안에 정답이 없으면 MRR은 0입니다. 같은 문서의 조각을 하나로 합치지 않고 각각 셉니다.
- 수준마다 두 방식을 합친 결과, 임베딩만, BM25만의 Recall@k와, 요구사항 번호가 정확히 맞은 후보의 Recall을 한 표로 비교합니다.
- 임베딩만 · BM25만의 순위는 각자의 점수 순서입니다. 여러 기관을 함께 찾을 때는 실제 검색처럼 기관별 목록을 번갈아 섞습니다. 가중치가 0인 방식은 후보를 내지 않습니다.
- 요구사항 번호 일치는 순위가 아니라 묶음이므로, k나 MRR 없이 정답이 그 묶음에 든 비율만 봅니다.

### 넘긴 근거 지표

답변 모델에 실제로 넘긴 조각으로 계산합니다.

- Evidence Coverage는 정답 청크 가운데 실제로 넘긴 비율입니다. Full Evidence Coverage는 정답 청크를 모두 넘겼으면 1, 아니면 0입니다.
- 근거가 하나인 질문과 여러 개인 질문(여러 근거를 잇는 질문, 비교 질문 등)을 따로 보고합니다. MRR은 첫 근거의 순위만 보므로, 근거를 모두 찾았는지는 알려 주지 않습니다.

### 채점에서 빼는 질문

- 청크 지표는 모든 정답 근거가 청크에 연결된 질문만 계산합니다. 일부만 연결된 질문에서 연결된 것만 골라 채점하지 않습니다. 문서 지표도 모든 근거가 문서에 연결된 질문만 계산합니다.
- 주제마다 전부 연결 · 일부 연결 · 연결 안 됨 질문 수와 제외율((일부 + 연결 안 됨) ÷ 답할 수 있는 골든 질문 수)을 `retrieval_exclusions.csv`에 저장하고, 비교 표에도 채점한 질문 수와 제외율을 함께 적습니다.
- 답할 수 없는 질문과 정답 근거가 없는 직접 작성 질문은 검색 지표에서 빼고 따로 셉니다.
- `retrieval.csv`에는 질문별 검색 지표, Evidence Coverage, 넘긴 글의 핵심 문구 일치, 검색 설정이 들어 있고, `generation.csv`에는 답변의 핵심 문구 일치가 들어 있습니다.

## dev 검색 전용 재실행

dev 답변 파일에 저장된 다듬은 질문을 그대로 써서, 검색 설정만 바꿔 다시 찾아볼 때 씁니다. 질문 다듬기, 답변 작성, 채점 API는 부르지 않습니다.

- 결과는 새 폴더에 원래 답변 파일과 같은 모양으로 저장되며, 05 검색 평가가 그대로 읽습니다. 실제로 쓴 청크 파일과 검색 설정도 함께 기록합니다.
- 답변은 새로 만들지 않으므로, 이 파일의 답변 · 근거 · 최종 점수를 새 설정의 성능으로 보면 안 됩니다.
- 원래 Langfuse 기록에 실험 점수가 덮어쓰이지 않도록, 새 파일에서는 Langfuse 기록 번호를 비웁니다.

```python
from rag.config import ARTIFACTS, load_config
from rag.retrieval.retrieval import HybridIndex
from rag.evaluation.evaluation import rerun_retrieval, evaluate_retrieval
from rag.evaluation.ir import component_table, coverage_table

cfg = load_config()
cfg["retrieval"].update(fusion="minmax", dense_weight=0.5, candidate_k=50, token_budget=2500)
path = ARTIFACTS / "dev_rerun" / "answers.jsonl"
rerun_retrieval(ARTIFACTS / "answers.jsonl", path, HybridIndex(ARTIFACTS, cfg))
scores = evaluate_retrieval(path, cfg)
display(component_table(scores, "doc"))
display(component_table(scores, "chunk"))
display(coverage_table(scores))
```

돈이 드는 확인은 모든 주제가 들어간 dev 30문항으로만 합니다.
실행하기 전에 설정 단가로 04(질문 다듬기, 답변)와 05(채점 두 가지)의 예상 비용을 보여 주고 승인을 받습니다.
실제 비용은 그 실행의 `api_usage.csv`로 계산합니다. 예전 실행의 질문당 채점 비용은 참고로만 보여 주며, 질문과 시점이 달라서 같은 질문끼리의 품질 비교로 보면 안 됩니다.

[30문항 표본 보고서](eval_ir_sample.md)에 표본 구성, 제외율, 예상 비용, 실제 결과가 있습니다.
이 보고서의 유료 결과는 dev `ab49a65`에서, 앞 대화를 반영한 질문 다듬기를 넣기 전에 잰 것입니다. 그 뒤의 검색 확인은 따로 적었고, 돈이 드는 평가를 다시 하지는 않았습니다.

## 최종 test 평가

dev로 검색 · 답변 설정을 정하고, test는 설정을 고정한 뒤 한 번만 실행합니다. test 결과를 보고 설정을 바꾸지 않습니다.

1. 최종 설정과 청크 · 색인을 고정합니다. 03의 첫 불러오기 셀과 입력 경로 셀을 실행한 뒤, 아래 코드로 test 평가 데이터를 만듭니다. 근거 연결 규칙은 dev와 같고, 원본 골든 파일은 바꾸지 않습니다.

   ```python
   test_items = load_eval_items(["eval/golden/test.jsonl"])
   test_labelled = label_evidence(test_items, chunks, raw_dir, package_dir, input_path)
   test_eval_set, test_report = check_eval_items(test_labelled)
   write_jsonl(test_eval_set, ARTIFACTS / "test_eval_set.jsonl")
   ```

2. 04의 평가 데이터 입력을 `test_eval_set.jsonl`로, 답변 출력을 `artifacts/test/answers.jsonl`로 바꿉니다.
3. 고정한 02 설정으로 04를 한 번 실행하고, 05의 `ANSWERS`를 그 test 파일로 바꿔 네 평가를 한 번 실행합니다.
4. 네 CSV와 제외율, 사용량을 최종 결과로 보관합니다. test는 검색 전용 재실행에 넣지 않습니다.

## 로컬 평가 입력과 OCR 캡션 복원

평가 자료와 저장된 OCR 결과는 git에서 내려받지 않습니다. 먼저 내 PC에 되살립니다.

```powershell
.venv\Scripts\python -m rag.validation.local_inputs
```

- 예전부터 쓰던 전체 clone이라면, git 기록에 남아 있는 파일에서 되살립니다. 이미 파일이 있으면 그것을 먼저 씁니다. 네트워크를 쓰지 않고, 원본을 지우거나 덮어쓰지 않습니다. 기록해 둔 dev · test 파일의 지문이 맞아야 새 파일을 만듭니다.
- 새로 받은 얕은 clone이나 기록이 정리된 저장소라면, 담당자에게 받은 비공개 묶음이 필요합니다.

  ```powershell
  .venv\Scripts\python -m rag.validation.local_inputs --from-directory C:/private/evaluation-bundle
  ```

- 묶음 안에는 `golden/dev.jsonl`, `golden/test.jsonl`, `golden/manifest.json`, `eval_questions.yaml`이 들어 있고, OCR 결과는 묶음 맨 위의 `ocr_captions.jsonl`입니다.
- 평가 자료만, OCR 결과만, 또는 둘 다 들어 있는 묶음을 같은 명령으로 되살릴 수 있습니다. 평가 파일이 하나라도 있으면 평가 묶음 전체가 있어야 하고 지문도 맞아야 합니다.
- 되살린 파일은 git에 올리지 않는 `artifacts/local_inputs/`에 둡니다. 설정에 적힌 예전 경로는 자동으로 이 폴더를 가리킵니다.
- test는 되살릴 때 지문만 확인하고, 검색이나 설정 조정에는 쓰지 않습니다. 필요한 자료가 없으면 되살리는 명령을 안내하고 멈춥니다.

주제별 핵심 문구는 숫자와 단위, 비교에서 고른 쪽, 조건, 표 칸의 값에서 뽑습니다. 근거가 여러 개인 질문은 각각 따로 확인할 수 있는 사실을 씁니다. 일부만 연결되거나 빠진 근거는 이유별로 나눠 셉니다.

## 정답 근거를 청크에 연결하기 (03)

### 필요한 입력과 문서 찾기

03에는 지금의 `artifacts/chunks.jsonl`과 `data/RFP_Preprocessing_Final_v11_Team/final_elements.jsonl`이 필요합니다.

- 직접 파싱한 경우, `config.yaml`의 `paths.input`이 폴더나 파일이면 원본을 그 자리에서 읽습니다. ZIP이면 01이 `artifacts/raw/`에 푼 파일을 찾되, 그 파일의 해시가 ZIP 안 파일의 해시와 같을 때만 씁니다. ZIP 안의 ZIP, 폴더 안의 ZIP에도 같은 규칙을 씁니다.
- 예전 실행이 남긴 다른 폴더는 뒤지지 않습니다. 푼 파일이 지금 ZIP의 내용과 다르거나, 해시가 다른 두 파일이 같은 이름을 쓰면 어느 문서인지 정할 수 없어 '문서 못 찾음'(`doc_unmapped`)으로 남깁니다.
- 골든 데이터에 적힌 문서 해시를 원본 파일의 해시와 맞추고, 파일 이름으로 지금의 청크 문서를 찾습니다.
- v11 패키지인 경우, 요소 정보에 적힌 원본 해시와 문서 번호, 파일 이름이 지금 청크와 같으면 연결합니다. 그래서 v11에서는 원본 파일이나 `artifacts/raw/`가 필요 없습니다.
- 파일 이름만 같다고 v11 해시를 직접 파싱한 결과에 쓰지 않고, 문서 제목이나 골든의 청크 번호로 짐작하지도 않습니다. 입력을 바꾸면 01과 03에서 같은 원본 경로를 쓰세요.

### 골든 근거 본문 되살리기

- 골든 데이터에는 고른 근거와, 고르지 않은 주변 글까지 담은 문맥이 따로 있습니다. 지금 dev에는 근거 716개와 문맥 덩어리 1,400개가 있습니다.
- 근거마다 적힌 위치로 v11 요소에서 본문을 되살립니다. 글은 적힌 범위를 잘라 내고, 표는 그 행의 칸을 열 순서대로 ` | `로 잇습니다.
- 되살린 본문이 문맥 덩어리 하나와 통째로 같은지 확인합니다. dev 716개, test 1,639개 모두 확인됐고, 같은 본문이 여러 덩어리에 반복된 경우는 각각 14개, 26개입니다.
- 근거 순서와 덩어리 순서를 억지로 짝짓거나 근거 여러 개를 하나로 합치지 않습니다. 이 위치는 골든 본문을 되살리는 데만 쓰고, 지금 청크의 위치로 옮기지 않습니다.

### 청크에 연결하는 규칙

- 근거와 청크 본문을 같은 방식으로 다듬습니다. 유니코드 표기를 맞추고, `|`를 공백으로 바꾸고, 겹친 공백을 하나로 줄입니다.
- 다듬은 근거가 같은 문서의 청크 안에 그대로 들어 있고, 그런 청크가 하나뿐일 때만 연결합니다. 비슷한 정도(유사도)는 쓰지 않습니다.
- 근거가 20자보다 짧거나 들어 있는 청크가 둘 이상이면, 같은 질문의 다른 문맥 덩어리(20자 이상)를 함께 품은 청크가 딱 하나일 때 그 청크로 연결합니다. 표 한 행처럼 짧은 근거를 같은 표의 다른 근거로 찾아가게 하려는 규칙입니다.
- 그래도 정하지 못하면 이유를 남깁니다. 문서를 찾지 못하면 `doc_unmapped`, 20자보다 짧으면 `too_short`, 들어 있는 청크가 없으면 `not_found`, 둘 이상이면 `ambiguous`입니다.
- 20자 기준은 짧은 숫자나 번호만으로 청크를 정하지 않으려는 고정 규칙이며, test 결과를 보고 바꾸지 않았습니다.

- 주제별 결과는 03과 `artifacts/golden_mapping.csv`, 문서별 결과는 `golden_documents.csv`, 덩어리 대응과 번호 점검은 `golden_correspondence.csv`에서 볼 수 있습니다.

### 03 화면과 저장 결과

- 03은 dev 근거를 최대 30쌍(seed 42로 무작위) 골라, 골든 본문과 연결된 청크 본문을 나란히 보여 줍니다. 30쌍보다 적으면 모두 보여 주고, 하나도 없으면 빈 표를 보여 줍니다.
