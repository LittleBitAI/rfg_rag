# ② 검색 — 동작과 설정

## 질문 재작성

02 검색 예제와 04 답변 생성은 검색 전에 `rag/retrieval/rewrite.py`로 질문을 재작성합니다.

- `config.yaml`의 `rewrite.model`, `rewrite.max_tokens`, `rewrite.reasoning_effort`가 이 API 호출에 적용됩니다.
- 검색과 기관 라우팅에는 재작성한 질문을 쓰고, 답변 생성·평가에는 원본 질문을 씁니다. 재작성 출력이 비면 원본 질문으로 검색합니다.
- 04는 평가셋 순서대로 답하며 직전 질문·답변 최대 10개를 다음 질문의 재작성 요청과 답변 생성 요청에 함께 전달합니다. 재작성에는 이전 대화를 인용한 글 하나로 보내, 모델이 이전 답변을 이어 쓰지 않게 합니다. 이전 대화는 질문 이해에만 사용하고 사실의 근거는 현재 검색한 문서로 제한합니다.
- 재작성 규칙의 예: 이어 묻는 질문에 앞 대화의 기관명·사업명 넣기, 비용·가격 질문은 '사업예산(사업비)', 사업 전반 질문은 '사업개요(사업명·사업기간·사업예산)', 자세히·평가 질문은 '사업개요, 추진배경, 사업목표, 사업범위'.
- 질문마다 재작성 API 호출 비용이 추가되며, 04의 `answers.jsonl`에는 검색용 질문·모델·토큰·비용·지연 시간을 `rewrite` 필드에 별도로 저장합니다.

## 하이브리드 검색

- Dense · BM25 후보(각각 상위 `candidate_k` 50개)는 기본으로 RRF(Reciprocal Rank Fusion, 후보마다 `Σ 1/(60 + 순위)`)로 합칩니다. 점수 크기가 아니라 각 검색의 순위만 써서, 척도가 다른 두 점수를 비율로 섞지 않습니다.
- 02 설정 셀에서 `FUSION = "minmax"`, `DENSE_WEIGHT = 0.8`로 바꾸면 두 점수를 0~1로 맞춘 뒤 Dense 80%·BM25 20%로 섞습니다. 7모델 벤치마크는 가중치를 바꿔 재므로 늘 `minmax`로 돕니다.
- 질문에 발주기관이 나오면 그 기관 문서 안에서만 찾습니다(`data/data_list.csv`의 `파일명` · `발주기관`).
- 요구사항 코드 일치 청크를 먼저 담고, 거의 같은 본문을 제외하며, `retrieval.token_budget`(기본 2500)으로 본문 토큰 합을 제한합니다. 첫 청크는 예산을 넘어도 유지합니다.
- 찾은 청크에 연결 청크(같은 요구사항의 ID · 명칭 / 상세 내용, 같은 표의 나뉜 부분)가 있으면 바로 뒤에 함께 담습니다.
- 전체 사업의 수량 조건(예: `예산 1억원 이상인 사업`)은 별도 필터로 처리합니다 — [수량 조건 검색](quantity_filter.md).

## 검색 글의 머리말

검색(BM25 · 임베딩)은 청크 글 앞에 머리말을 붙인 글을 읽습니다. 답변 근거와 화면에는 원래 글을 그대로 씁니다.

- 요구사항 머리말: 요구사항에 속한 청크의 글에 그 요구사항 ID나 명칭이 없으면 `[요구사항 TST-901 시험 데이터 보관]`을 붙입니다. ID · 명칭 청크와 상세 내용 청크가 나뉘어도 상세 내용이 찾히게 합니다.
- 절 제목 머리말: `3 | 구축범위`처럼 제목이 한 줄 표로 읽혀 따로 청크가 된 문서는, 그 절의 청크 앞에 `[구축범위]`를 붙입니다. 다음 제목 청크나 섹션 정보가 있는 청크가 나오면 멈춥니다.

## 노트북 설정과 저장 파일

- 설정 셀은 메모리의 설정을 바꾸며 `config.yaml`을 덮어쓰지 않습니다. 02는 적용한 rewrite·검색 설정을 `artifacts/retrieval_settings.jsonl`에 저장하고 04와 질문 화면이 읽습니다. 기존 색인을 재사용할 때도 02의 설정 셀을 실행해 이 파일을 만든 뒤 04를 실행하세요.
- 모델을 바꾸면 같은 설정 셀의 `*_PRICES`도 해당 모델의 입력 · 캐시 입력 · 출력 단가(USD / 100만 토큰)로 맞추세요. 재작성·답변 기본값은 [GPT-6 LUNA Standard 단가](https://developers.openai.com/api/docs/models/gpt-6-luna)를 사용하며 평가 심판은 [gpt-5-mini 단가](https://developers.openai.com/api/docs/models/gpt-5-mini)를 유지합니다. 설정 단가는 비용 추정용으로 실제 청구와 다를 수 있습니다. [수량 필터 전체 견적과 네 질문 비교](quantity_filter_estimate.md)에 범위·실사용량·모델 선택의 한계를 기록합니다.
- 청킹 크기를 바꾸면 01부터 다시 실행합니다. 검색 설정 조절은 저장 rewrite가 있는 dev에서 [검색 전용 재실행](evaluation.md#dev-검색-전용-재실행)으로 비교할 수 있습니다. 새 설정의 답변·심판 결과가 필요하면 04도 다시 실행합니다.

## 색인 지문과 재구축

- `bm25_tokens.json`은 토큰과 지문을 함께 저장합니다. 지문은 줄바꿈을 정규화한 `indexing.py` 전체 코드, 생성 사전, `kiwipiepy`·모델 데이터·`hanja` 버전을 포함합니다. 따라서 이 모듈의 토큰 규칙 외 변경도 보수적으로 재구축을 요구합니다.
- 지문이 없거나 현재 코드·사전·패키지와 다르면 검색 시 오류로 중단합니다. 이때 02의 불러오기·설정 셀과 `1. 색인 만들기`의 `build_index` 셀을 실행한 뒤 04나 질문 화면을 실행하세요. 이 재구축은 로컬 작업이며 유료 질문 재작성 예제 셀을 실행할 필요가 없습니다.
- 02는 FAISS, BM25 토큰, 수량 행, 항목명과 항목명 벡터를 옆의 임시 폴더에서 만듭니다. 수량 임베딩과 요약 계산이 성공한 뒤에만 완성된 폴더를 게시하고, 게시 중 이름 바꾸기가 실패하면 이전 폴더를 되돌립니다. 이 되돌리기는 색인 파일 다섯 개에만 해당하며 전처리 청크 파일은 바뀌지 않습니다. 동시에 읽는 프로세스나 프로세스 중단까지 보장하는 트랜잭션은 아닙니다.
- 색인을 다시 만든 뒤 코드를 되돌리면 색인도 함께 되돌려야 합니다. [읽기 프로세스를 멈춘 뒤의 되돌리기 절차](index_rollback.md)를 따르세요: 새 색인을 격리하고, 되돌릴 리비전·환경 그대로 다시 만들어 확인한 뒤, 읽기 프로세스를 다시 켜기 전에 완성된 폴더를 게시합니다. 코드만 되돌리거나 새 파일에서 토큰 배열만 꺼내 쓰는 방법은 지원하지 않습니다.

## 04가 저장하는 검색 기록

- 답변 생성도 실제 응답 모델·캐시 입력 토큰·비용을 저장합니다. 05는 저장된 비용을 사용하므로 평가 시 설정을 바꿔도 이전 생성 비용이 바뀌지 않습니다.
- `latency_s`는 재작성·검색·답변 생성 전체 시간입니다. `end_to_end.csv`의 `cost_usd`는 rewrite + 답변 생성 비용이며 `rewrite_cost_usd`, `answer_cost_usd`로 구분됩니다. OCR과 평가 비용은 별도로 집계합니다.
- `ranked_candidates`에 패킹 전 후보의 `chunk_id`, `doc_id`, `fused_rank`, `dense_score`, `dense_rank`, `bm25_score`, `bm25_rank`, `exact_code_match`를 저장합니다. 순위는 1부터 시작하며 해당 성분의 후보가 아니면 점수·순위는 null입니다.
- `context_chunk_ids`는 실제 LLM에 보낸 청크 ID입니다. `retrieval_settings`는 `fusion`, `dense_weight`, `candidate_k`, `token_budget`, 활성 `chunk_file`, `k_values`(5,10,20), `stored_rewrites_reused`를 기록합니다.
- 04는 라벨 필드가 없는 옛 eval_set을, 05의 네 함수는 새 검색 기록·rewrite 등이 없는 옛 answers를 유료 호출 전에 거부합니다. 빠진 필드를 확인하고 03 → 02 설정 셀 → 04 → 05를 실행하세요.
- `search()`의 반환값은 유지하며, `search_with_candidates()`는 같은 검색 결과와 읽기 전용 후보 스냅샷을 함께 반환합니다.
