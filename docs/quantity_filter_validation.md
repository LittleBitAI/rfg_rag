# 수량 필터 검증 기록

수량 필터는 "예산 1억원 이상인 사업"처럼 숫자 조건이 붙은 질문에, 조건에 맞는 사업을 모두 찾아 표로 답하게 하는 기능입니다. 아래 네 질문으로 검증했습니다.

- 2026-10-17에 최종 답변 4개가 모든 검사를 통과했고, 사용자가 질문 화면에서 61개 사업 표와 제외 10건을 직접 확인했습니다.
- 그 뒤 코드 검토를 여섯 차례 받아 표를 읽는 부분의 결함을 고쳤습니다. 고칠 때마다 실제 문서 전체(청크 18,989개)를 다시 읽어 영향 범위를 셌고, 네 질문의 결과는 한 번도 바뀌지 않았습니다.
- 검토 수정은 API를 부르지 않고 따로 만든 색인에서만 확인했습니다. 질문 화면에 반영하려면 `02_retrieval.ipynb`로 색인을 다시 만들어야 합니다.

| 질문 | 맞는 사업 | 제외 |
| --- | ---: | ---: |
| 예산 1억원 이상인 사업과 개요 | 61 | 10 |
| 사업기간 6개월 이상 | 30 | 45 |
| 예산 1억~5억원 | 44 | 10 |
| 최대 예산 | 1 | 10 |

"제외"는 값을 찾지 못했거나 정책상 뺀 문서 수이며, 값이 있지만 조건에 못 미친 문서는 들어가지 않습니다.

이 문서에는 집계 수치와 측정 조건만 적었습니다. 실제 질문·사업명·개요·근거 문장은 공유하지 않는 로컬 폴더 `artifacts/`에만 있습니다. 수치는 당시 실행 기록(정리 전 커밋 `d7d1682^`)을 옮긴 것이며, 이번에 다시 측정하지 않았습니다. 비용은 [수량 필터 검증 비용](quantity_filter_estimate.md)에 있습니다.

## 유료 검증

시간 순서대로 적었습니다. 모두 GPT-6 LUNA를 썼고, 대화 이력은 비우고 추론 강도는 `low`, 답변의 최대 출력은 8,192토큰(추론 포함)으로 두었습니다. 유료 채점 모델, OCR, 임베딩 API, test 평가는 실행하지 않았습니다.

자동 검사는 행 수, 출처, 원래 값 문자열, 개요 열 이름, 제외 문구만 봅니다. 뜻이 맞는지는 채점하지 않으며, 유료 채점 점수도 없습니다.

그래서 유료 호출 없이 아래를 고쳤습니다.

- 수량 질문에서 `규모` 같은 군더더기 말을 뺍니다.
- 개요는 값이 나온 발췌보다 실제 사업 소개를 먼저 고르고, 빈 서식은 후보에서 뺍니다.
- 지시문에 값을 원문 그대로 옮기라는 규칙을 더 분명히 적었습니다.
- 표 칸 안의 항목 이름을 일반적인 열 이름보다 먼저 쓰고, 사업 정보는 금액 항목에만 붙입니다.
- 항목 이름이 붙은 수량 상한은 예산뿐 아니라 사업기간에도 씁니다. "~이내인 업체"처럼 자격을 정하는 문장은 계속 뺍니다.
- 참고 자료로 인용된 값은 그 사업의 값으로 쓰지 않습니다.

네트워크를 막고 다시 실행했을 때 맞는 사업 61/30/44/1개와 제외 10/45/10/10개가 그대로였습니다. 저장된 재작성 4개의 사업 순서와 제외 수, 되찾은 금액 30개와 기존 금액 88개도 모두 같았습니다. 잘못 고른 기간 7행은 빼거나 실제 사업기간으로 바꿨습니다. 개요는 실제 절 제목 아래의 목적과 배경을 먼저 쓰고, 목차 번호를 정리하며, 일반 요구사항 문단에 우연히 나온 말은 개요로 쓰지 않습니다. 저장된 dev 질문 60개는 답변 모델에 넘어간 청크 순서가 모두 같았습니다.

수량 필터 테스트 92개와 전체 테스트 1,182개가 통과했고(경고 12개, 407.29초) ruff 검사도 통과했습니다. 질문 화면을 고친 데이터로 다시 띄웠고, 답변 호출 없이 화면과 서버가 정상으로 응답하는 것(HTTP 200)을 확인했습니다.

### 2차: 표 양끝의 `|`, 사업이 아닌 질문, 색인 교체

커밋 `684c463`에서 결함 세 가지를 재현했습니다(새 테스트 24개 중 22개 실패).

1. 양끝에 `|`가 붙은 합계 행 `| 계 | 200,000 |`을 읽으면 칸이 하나 밀려, 금액이 예산 열이 아닌 다른 열로 갔습니다. 그래서 1억 4천만 원과 6천만 원짜리 부분 금액만 남았습니다.
2. 사업이 아닌 대상(예: 응답 시간 요구사항)에 숫자 조건이 붙은 질문이 하이브리드 검색(뜻으로 찾기와 단어로 찾기를 함께 쓰는 검색) 없이 수량 필터로만 처리됐습니다.
3. 색인을 다시 만들다가 중간에 실패하면, 검색 색인은 새것으로 바뀌고 수량 데이터는 옛것으로 남아 둘이 섞였습니다.

고친 내용은 다음과 같습니다.

- 수량 칸을 읽는 네 곳이 같은 칸 나누기 방식을 쓰게 했습니다. 표 바깥의 `|`는 떼고, 안쪽 빈 칸은 그대로 둡니다. 양끝 `|`, 줄바꿈 방식, 파일 끝, 뒤따르는 글, 바깥 공백, 빈 칸을 조합한 10가지 경우를 테스트합니다. 1억 5천만 원을 기준으로 하면 모든 형식에서 합계 `200,000 (천원)`을 고릅니다.
- 조건 뒤에 "사업" 같은 대상이 있을 때만 사업 필터로 보냅니다. 사업이 아닌 비교 질문 5개를 원래 질문과 재작성 질문으로 나눠 10가지 경우를 테스트합니다.
- 색인 파일 다섯 개(의미 검색 색인, 단어 검색용 토큰, 수량 데이터, 항목 이름, 항목 이름 벡터)를 모두 만든 뒤 한꺼번에 바꿔 넣게 했습니다. 중간에 실패하면 옛 색인이 그대로 남아 검색됩니다. 네 단계에서 일부러 실패를 일으켜 확인했습니다. 다만 프로그램 오류가 났을 때 되돌리는 것이고, 컴퓨터가 갑자기 꺼지는 경우까지 막지는 않습니다. 자세한 내용은 [색인 되돌리기](index_rollback.md)에 있습니다.

청크 18,989개 중 표가 있는 13,627개(단위 선언이 있는 6,968개 포함)를 다시 읽었고, 바뀐 수량 행은 없었습니다. 양끝 `|` 문제는 테스트로 재현한 것이며, 지금 문서에서 고른 예산이 바뀐 것은 아닙니다. 사업이 아닌 실제 질문 5개는 하이브리드 검색으로 각각 14/17/15/23/15건을 찾았습니다. 영향받은 테스트 파일 10개에서 694개가 통과했습니다(경고 12개, 131.46초).

### 3차: 값이 빠진 행과 "전체 사업"

커밋 `51629a7`에서 결함 두 가지를 재현했습니다(새 테스트 35건 실패).

1. 표 중간에 `A 사업 | -`처럼 값이 없는 행이 있으면, 머리글과 단위 선언이 이 행으로 바뀌어 다음 행의 값이 사라졌습니다. 이 행이 없으면 다음 행 `B 사업 | 100`은 천원 단위를 받아 100,000원으로 바르게 읽힙니다.
2. "전체 사업" 같은 질문을 사업 질문으로 알아보지 못했습니다. 형태소 분석기 Kiwi가 `인 / 전체 / 사업`으로 나눈 뒤 `전체`에서 멈춰서, 조건은 맞게 읽고도 하이브리드 검색으로 갔습니다.

고친 내용은 다음과 같습니다.

- 머리글 이름과 단위 선언을 함께 유지합니다. 수량이 없는 데이터 행은 머리글을 바꾸지 않습니다. 표의 시작이나 단위가 분명히 적힌 새 머리글은 계속 머리글로 봅니다. 숫자가 든 항목/값 행이나 숫자만 있는 칸은 데이터로 봅니다.
- 고치는 중간에 두 번 잘못 판단한 것을 최종 측정 전에 바로잡았습니다. 숫자가 든 항목/값 행을 머리글로 본 경우와, 실제 머리글 `비고`를 머리글이 아니라고 본 경우입니다.
- `전체`는 범위를 좁히지 않는 말로 처리합니다. 다른 명사를 만나면 멈추므로, 문장 뒤쪽에 "사업"이 나와도 요구사항이나 업체에 대한 질문이 사업 필터로 가지 않습니다. 원래 질문과 재작성 질문을 짝지은 16가지 경우를 테스트합니다.

2차와 비교해 문서 79개의 청크 185개가 바뀌었습니다. 단위를 물려받은 행이 34개 늘고 14개 줄었으며, 기존 항목 이름 372개가 바뀌어 수량은 29,359행이 됐습니다. 늘고 준 행은 금액이 아니고, 기존 금액 항목 이름 21개가 바뀌었습니다. 새로 생긴 단위에는 점수표와 인월·인일 표가 있지만, `동작`이나 `기준`처럼 엉뚱한 단위도 남아 있습니다. 숫자와 단위의 원문 위치는 모두 대조했지만, 모든 행의 뜻이 맞다고 보장하지는 않습니다.

영향받은 테스트 파일 10개에서 740개가 통과했습니다(경고 12개, 54.12초). 사업이 아닌 질문 8개는 하이브리드 검색으로 각각 14/17/15/23/15/18/14/17건을 찾았고, `전체`를 넣은 질문도 넣지 않은 질문과 값·후보·근거가 같았습니다.

### 4차: 번호가 붙은 단위 머리글과 `이내`·`까지`

수정 전 코드에서 결함 두 가지를 재현했습니다.

1. `구분 | 1차 예산(천원)` 머리글에서 `1차`만 수량으로 읽고 100,000원을 빠뜨렸습니다.
2. `사업기간 6개월 이내인 사업`과 `사업기간 6개월까지인 사업`은 조건을 읽지 못해 일반 검색으로 갔습니다. 조건을 직접 만들어 넣어도 7개월을 통과시켰습니다.

고친 내용은 다음과 같습니다.

- 숫자가 있다는 이유만으로 머리글이 아니라고 보지 않고, 칸마다 항목 이름과 끝의 단위 선언을 확인합니다. 머리글로 확인되면 열 단위를 정하고, 차수나 연도는 수량으로 내보내지 않습니다. 숫자 데이터 칸, 단위가 직접 적힌 값, 본문 문장, 괄호 속 약어는 그대로 데이터로 둡니다. 실제 문서에서 찾은 BIS 사업명, TLS 서버 수량, DMZ 조항도 테스트로 남겼습니다.
- `이내`와 `까지`를 그 값을 포함하는 상한으로 처리합니다. `부터…까지` 범위, 기관이나 문서 이름으로 시작하는 질문, 사업이 아닌 대상, 맞는 결과가 없는 경우는 기존대로 둡니다.

29,359행 중 머리글 번호를 수량으로 잘못 읽은 1행이 빠져 29,358행이 됐습니다. 늘어난 수량이나 바뀐 항목 이름은 없습니다. `6개월 이내`와 `6개월까지`는 각각 37개 사업·제외 45개, `1억원 이내`와 `1억원까지`는 각각 30개 사업·제외 10개로, `이하`로 물었을 때와 값·순서·근거가 모두 같았습니다. 사업이 아닌 질문 10개는 일반 검색을 그대로 썼습니다. 전체 테스트 1,311개(경고 12개, 134.80초)와 수량 필터 테스트 215개가 통과했습니다.

### 6차: 값이 빠진 행을 구분선으로 잘못 봄
