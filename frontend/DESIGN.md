# 질문 화면 디자인

```
누가:   RFP 를 검토하는 팀원
무엇을: 제안요청서에 대해 묻고, 답의 근거 문단을 바로 확인한다
성공:   답변의 [n] 을 누르면 답변 옆에 그 출처의 원문 청크가 열린다
```

## 배치

데스크톱 화면이다. 왼쪽 대화 열에서 읽고, 오른쪽 출처 칸에서 근거를 본다 — 근거를 보려고 스크롤하지 않는다.
사이드바(스레드 목록)는 없다 — 대화는 탭 하나에만 있다.

```
┌ RFP 질의응답 ────────────────────────────────────── 새 스레드 ┐  ← 붙는 상단 바
│                    ╭ 질문 말풍선 ╮  │ 출처                      │
│                    ╰─────────────╯  │ 질문 한 줄 (meta)          │
│ ▣ 문서 도우미                        │ 1 파일 이름…        p.176 │  ← 두 줄 카드, 위에 고정
│   답변 본문 … [1] … [2]              │   청크 첫머리…            │
│   …                                 │ ┃ [1] 파일 p.176          │  ← 펼친 청크는 목록 아래
│                    ╭ 다음 질문 ╮    │ ┃ 청크 본문 (표 포함)      │
│ ╭ 이어서 질문하기               ╮    │ ┃ …                       │
│ ╰ Enter 보내기 · Shift+Enter  ↑ ╯    │                           │
└─────────────────────────────────────┴───────────────────────────┘
       ↑ 대화 열 아래에 붙는 입력 상자       ↑ 상단 바 아래에 붙고 따로 스크롤
```

- 채팅 형태인 이유: 질문을 제목처럼 크게 쓰고 답을 그 아래 펼친 판은 "입력 · 출력의 채팅 직관성이 떨어진다"는 피드백을 받았다.
  누가 말했는지가 위치(오른쪽 말풍선 = 나, 왼쪽 이름표 = 문서 도우미)로 바로 보이게 했다. 답변은 말풍선에 넣지 않는다 — 표 · 목록이 긴 답이 좁은 상자에 갇힌다.
- 기다리는 동안 이름표 아래에 움직이는 점 세 개와 "문서를 찾는 중…" 을 보인다. 답이 오면 입력 상자로 포커스를 돌려 바로 이어 물을 수 있다.
- 입력 상자는 글 칸 아래에 안내(Enter 보내기 · Shift+Enter 줄바꿈)와 보내기 버튼을 둔다. 480px 이하에서는 안내를 숨긴다.

- 출처를 답변 옆에 두는 이유: 처음 판(답변 위 카드 격자)은 넓은 화면의 양옆을 비워 두고 근거를 보려면 스크롤해야 해서
  "모바일 같다"는 피드백을 받았다. 옆 칸은 그 폭을 근거에 쓰고, 답변은 그대로 화면에 남는다.
- 출처 칸은 마지막 턴의 출처를 보여 주고, 이전 턴의 `[n]` 을 누르면 그 턴의 출처로 바뀐다. 칸 위의 질문 한 줄이 어느 턴인지 알려 준다.
- 카드는 두 줄(번호 · 파일 이름 · 쪽 / 청크 첫머리)로 위에 고정하고 청크는 목록 아래에 연다. 카드 바로 밑에 펼치면 긴 청크가 다른 카드를 밀어낸다.
  첫머리 줄이 있는 이유: 한 질문의 출처가 같은 파일인 경우가 많고 HWP 는 쪽 번호도 없어서 파일 이름만으로는 카드가 구별되지 않는다.
- 1024px 보다 좁으면 한 열로 접고 같은 카드 · 청크를 답변 위에 보인다.

## 글자 단계

네 단계(display · body · label · meta)만 쓰고, 한 단계가 두 가지 뜻을 갖지 않는다.
예전의 question 단계(26px 질문 제목)는 채팅 형태에서 말풍선(body)으로 바뀌어 없앴다 — 질문과 답이 같은 크기여야 대화로 읽힌다.
label 은 "구역 이름"(문서 도우미 · 출처)과 "출처 번호"(칩) 둘 다지만 둘 다 '본문 바깥의 표지'라는 한 가지 뜻이다.
글꼴은 Pretendard 다. 운영체제마다 다른 시스템 글꼴(Windows 맑은 고딕, macOS Apple SD 고딕) 대신 어디서나 같은 모양 · 같은 굵기 단계로 보이게 했다.
동적 서브셋이라 화면에 쓰인 글자 조각만 내려받는다.
굵은 글씨와 표 머리(`strong` · `th`)는 단계가 아니라 강조로 600 을 쓴다 — 답변 안에서는 body, 청크 안에서는 meta 크기.
처음 판의 13px 단계는 "흐리고 작다"는 피드백으로 없앴다. 가장 작은 글자가 15px 이다.

## 색

글자와 바탕은 무채색이고, 강조색(청록)은 근거로 가는 길과 대화의 두 주체에만 쓴다 — 보내기 버튼, `[n]` 칩, 펼친 출처 카드의 테두리,
질문 말풍선(옅은 청록), 문서 도우미 아이콘 · 기다림 점.
그래서 눈이 본문에서 칩으로, 칩에서 카드로 따라간다. 청록 · 파랑 · 무채색 후보 중 청록을 골랐다 (파랑은 답변 속 링크와 겹치고, 무채색은 칩이 묻힌다).
