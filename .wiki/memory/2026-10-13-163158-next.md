# Key-fact scorer fixed to understand numbers, dates and negation; PR #11 merged

A report said `_key_fact_ratio` in the evaluation pipeline accepted wrong numbers and negated conditions as matches, and rejected the same amount written another way. The user asked whether this was true and for a fix to read numbers, dates and negation correctly without hardcoding. The user chose the branch name, the negation handling, the rule for numbers without units and the form of proof. The fix shipped as PR #11. A review loop was blocked by uncommitted `.wiki` files, and the PR was later merged at review round 5 with no P2 issues left.

## Decisions

- Use branch `feature/evaluation-key-fact-matching` for the scorer fix — A branch named `dev` already exists, so `dev/feature/...` cannot be created. Teammates name their branches `feature/...`. (rejected: `dev/feature/...` as originally requested)
- For negation, check the qualifier window only outside the matched span — Otherwise a fact that is itself negative, such as `부가세 별도` or `불포함`, would be rejected when it matches correctly. (rejected: Applying the negation window to the matched text, which includes the fact itself)
- Numbers without a unit fall back to whole-number matching
- Prove the fix with tests only
- Test values must go beyond the report's own examples: other amounts, another date and other negation words — So that a special case written for `1억 3천만원` cannot pass.

## Facts

- `_key_fact_ratio` lives only in `rag/evaluation/evaluation.py`. Before the fix it removed whitespace and commas, lowercased, and tested a plain substring. A fact `A|B` matched if either alternative appeared. As a result `3초`⊂`13초` and `포함`⊂`불포함` matched, while `1억 3천만원` vs `130,000,000원` did not. (unverified)
- `key_facts` comes from the validation pipeline's `evidence_keywords`. (unverified)
- Only `key_facts_in_context` (Retrieval table) and `key_facts_in_answer` (Generation table) use `_key_fact_ratio`. The LLM-judged RAGAS metrics do not: context_precision/recall, answer_relevancy, faithfulness and factual_correctness. The table value is the fraction of a question's facts that matched. (unverified)
- ruff limits each function to complexity 8, so the number, date and negation parsers need to be separate small functions. (unverified)
- `tests/test_smoke.py` only checks that modules import. It does not test scorer behaviour. (unverified)
- A local and remote branch named `dev` exists, so `dev/...` branch names fail. Teammates' branches are `feature/Generation`, `feature/Retrieval`, `feature/preprocessing`, `feature/question-rewrite` and `dev-feature-ssh-gpu-workspace` (PR #4). (unverified)
- PR #11 is on `feature/evaluation-key-fact-matching`. Its commits are the matcher fix `d0f1b39` and the PR-writing rule page `adb2e5e`. (unverified)
- The review loop's uncommitted-changes check counts every dirty file in the working tree. It was blocked by `.wiki/.sync`, a tracked timestamp that is rewritten on every wiki sync, and by untracked `.wiki/decisions/2026-10-12-001…` to `2026-10-13-010-dev.md`, which were carried over from `dev`. (unverified)
- Unblocking without losing the files: `git stash push -u -- .wiki/.sync .wiki/decisions`, rerun the loop, then `git stash pop`. Avoid `git checkout -- .wiki` and `git restore`, and do not commit those files to the feature PR. (unverified)
- PR #11 merged at review round 5 with 0 P2 issues remaining.

## Preferences

- Do not hardcode the report's examples (`1억 3천만원`, the date, the negation words). The fix must be general for numbers, dates and qualifiers.
- The user's pipeline is evaluation and validation only. Do not touch other pipelines.
- Check how teammates named their branches and follow the same convention.
