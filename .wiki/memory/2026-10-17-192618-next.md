# Fix spec for budget-threshold questions: metadata filtering with a Kiwi quantity parser (PR #63 merged)

The user reported that "사업 예산 1억원 이상인 사업들과, 그 사업들의 개요를 알려줘." returns "not found". They asked for a root-cause analysis and a fix spec. The cause given was that top-k hybrid retrieval returns threshold-rule passages, that no per-document budget is stored, and that the 2500-token context cannot hold a full list. The agreed fix uses metadata filtering. A unit-agnostic, LLM-free parser copied from golden_pipeline extracts amounts at index time, a filter route handles threshold, range and extremes questions, fields are matched by local embedding similarity, and all matches go into a compact context. The work was merged as PR #63 (round 8, 0 remaining P2).

## Decisions

- Extract budgets by metadata filtering with a parser that is not tied to any fixed unit and makes no LLM calls; "1억 3천", "130백만" and "130,000,000" must all parse to the same value — The user said the earlier options were poor because they were hard-coded, and that recognition must not be limited to particular units; LLM calls are not allowed (rejected: The three earlier budget-source options (1, 2, 3); hard-coded unit lists; LLM-based extraction)
- Question coverage: threshold plus range and extremes (largest/smallest)
- Long lists: return all matches in a compact context
- Field matching (deciding that 예산/사업비/사업금액/추정가격 mean budget) by local embedding similarity — To avoid a synonym list
- Copy the Kiwi-based parser from golden_pipeline into rag/retrieval — golden_pipeline is deliberately kept separate from rag/ (rejected: Importing it from golden_pipeline)

## Facts

- The failure is architectural: the question needs a numeric filter across all 98 RFPs, but the pipeline only fetches top-k similar passages, and the passages containing "1억원 이상" are mostly threshold rules such as committee-size tables and the SW사업 definition (unverified)
- docs.jsonl holds the title, cover and opening text but no budget; data/data_list.csv has only the columns 파일명 and 발주기관 (unverified)
- Chunk recognized_fields contain unlabelled `money` entries, and no code in rag/ reads them (unverified)
- The context limit is token_budget: 2500, about 5–10 chunks (unverified)
- A rough regex check found budget labels with amounts in 60 of 98 docs; 45 state a full won figure, and 28 of those are 1억원 or more (unverified)
- golden_pipeline has a Kiwi-based quantity reader, facts(). It takes the unit from the POS tags after the number, multiplies the numeral words 십/백/천/만/억/조, and returns the preceding words as the subject (unverified)
- rag/evaluation/evaluation.py also parses numbers but uses a fixed unit list, so it is not a suitable base (unverified)
- Design: at index time every amount becomes a metadata row (doc, chunk, value, unit, subject, original text). An amount followed by 이상/이하/초과/미만/이내/까지 is marked as a threshold, not a document value (unverified)
- Design: the filter route is used only when the question has a comparison and no agency is named. Questions with a document-name prefix route as before, and every golden dev question has such a prefix (unverified)
- Design: the overview comes from running the hybrid ranker inside each qualifying document using the rest of the question. The context reports how many documents had no matching value (unverified)
- The change touches rag/retrieval, one rule in the rag/generation prompt, and the 02 notebook rebuild (unverified)

## Preferences

- No hard-coding: amount recognition must not be limited to specific units
- No LLM calls for extraction
- Before any paid rewrite or answer call, show a price estimate and wait for approval

## Open

- The similarity cut-off for field matching must be chosen by inspecting the real per-document matches on the local index
- Whether 추정가격 counts as budget depends on the cut-off; the implementer must record the outcome
- Seeing the final answer in the app needs paid calls, pending the user's approval
