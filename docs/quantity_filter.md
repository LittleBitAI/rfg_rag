# 전체 사업의 수량 조건 검색

기관명이나 문서명 없이 사업(`사업`)을 대상으로 한 수량 조건은, 색인에 저장한 문서별 값으로 전체 문서를 거릅니다.
기준값 · 범위 · 최대/최소를 지원하며 같은 값(동점)은 모두 남깁니다.

예: `사업 예산 1억원 이상인 사업들과, 그 사업들의 개요를 알려줘.`, `사업기간 6개월 이상인 사업`, `예산이 1억~5억인 사업`, `예산이 가장 큰 사업`

- 요구사항이나 업체 자격을 대상으로 한 숫자 비교는 기존 하이브리드 검색을 씁니다. 항목명에만 '사업'이 들어 있으면 사업 필터를 고르지 않습니다.
- 라우팅은 저장된 재작성 질문을 쓰고, 재작성이 비었으면 원래 질문을 씁니다.
- 범위 수식어 `전체`는 사업 대상 앞에 올 수 있습니다. `예산 1억원 이상인 전체 사업`은 수식어 없는 형태와 같은 필터와 기본 개요 문맥을 씁니다. 요구사항이나 업체 앞의 같은 수식어는 하이브리드 검색을 유지하며, 뒤에 사업을 언급하는 질문도 마찬가지입니다. 이 규칙은 범위가 정해져 있어 임의의 제한 수식어를 해석하지 않습니다.
- `이내`와 단독 `까지`는 `이하`와 같은 포함 상한입니다. `사업기간 6개월 이내인 사업`과 `사업기간 6개월까지인 사업`은 6개월을 포함하여 오름차순으로 모든 일치 사업을 반환합니다. `부터…까지`는 기존의 양 끝값 포함 범위를 유지합니다.

## 수량 색인

수량 추출을 바꾸면 02에서 색인을 다시 만드세요. `artifacts/index/quantities.jsonl`은 수량마다 문서·청크·값·단위·정리한 항목명·원문 범위를 저장합니다.
서로 다른 항목명은 기존 로컬 Embedder로 한 번씩 임베딩합니다. 띄어 쓴 항목명과 표 머리글을 복원하고, 단위는 Kiwi 품사로 읽습니다.
한글 금액, 앞쪽 통화 기호, 확인된 단위 중복 오타는 로컬에서 정규화합니다. 색인·라우팅·필터에 LLM이나 API 호출을 추가하지 않습니다.

## 값으로 쓰는 것과 쓰지 않는 것

- 비교 표현은 경계로 표시된 채 남습니다. `사업예산: 230,000천원 이내`, `사업기간: 계약일로부터 24개월 이내`처럼 항목명이 붙은 명시적 상한은 문서 값이 될 수 있지만, 자격 조항 · 예시 · 명시적 참고 블록은 될 수 없습니다.
- 추정가격(`추정가격`)은 계속 제외합니다.
- 1원 이하의 원 값은 미표기로 봅니다. 1개월 · 1건 같은 유효한 수량은 그대로 씁니다.
- 괄호 안 통화 배율은 단위를 선언합니다. `건당`처럼 세는 단위만 있는 항목명은 예산 항목이 될 수 없습니다.
- 표 칸의 주어가 일반 머리글보다 우선합니다. 사업 문맥은 금액 항목명에만 덧붙여, 관련 없는 기간은 실제 주어를 유지합니다.

## 표의 단위 읽기

- 선언된 열 단위와 앞의 `(단위: 천원)`은 숫자 표 칸에 적용됩니다. `사업예산(천원) | 부문` 다음의 `10 | 운영`은 10,000원이 됩니다. 메타데이터는 숫자 칸과 단위 선언 범위를 모두 보존하고, 문맥에는 `10 (천원)`으로 표시합니다.
- 칸에 명시된 단위가 우선하며, 물려받은 단위는 표나 청크가 끝나면 끝납니다. 구성 행의 항목명은 줄인 합계 행과 구별됩니다.
- `과업비/과업기간: 100,000천원/5개월`처럼 빗금으로 나란히 적은 항목은 값마다 해당 항목에 배정합니다. `MB/s`처럼 단위 안의 빗금은 그대로 둡니다.
- 양 끝의 선택적 파이프, 바깥 공백, LF/CRLF 줄끝은 표 열을 늘리지 않습니다. 안쪽 빈 칸은 자리를 유지합니다. 줄인 합계 행은 기존의 '유일하게 선언된 열' 복구를 그대로 씁니다. 임의의 병합 칸을 추론하거나, 유사도가 더 높은 항목보다 합계를 우선하지 않습니다.
- 데이터 값이 없거나 글이면 현재 열 이름과 단위는 그대로 유지됩니다. 표 스키마는 이름만 있는 행에서 시작하고, 다른 이름만 있는 단위 선언 행에서 바뀌며, 기존의 파이프 없는 표 경계나 청크 끝에서 초기화됩니다. 숫자 키/값 행은 데이터로 남습니다. 구분자 없는 글에서 표시 없이 이어지는 머리글 변화는 모호한 채로 두며, 선언이나 지원하는 경계가 있어야 합니다.
- 선언 단위 머리글에는 `1차 예산(천원)`이나 `2026년 1차 예산(천원)`처럼 숫자 수식어가 있어도 됩니다. 수식어 뒤의 항목명과 끝의 단위 선언을 확인하여 열 단위를 설치하며, 머리글의 차수·연도는 데이터 수량으로 내보내지 않습니다. 숫자 셀, 명시 단위 값, 괄호 약어가 섞인 본문은 데이터로 유지합니다.
- Markdown 구분선 행도 단위 선언 머리글 전체를 알려 줍니다. 예를 들어 `--- | --- | ---` 위의 `구분 | 2024년 | 예산(천원)`은 연도가 다른 칸에 있어도 예산 열에 천원 배율을 설치합니다. 머리글 숫자는 데이터로 내보내지 않습니다. 이런 구조 표시가 없으면 기존 칸 단위 검사를 그대로 적용하며, 번호가 붙은 데이터 행은 괄호가 있다는 이유만으로 옆 칸에 선언을 설치하지 못합니다.
- 구분선 칸마다 하이픈이 세 개 이상 있어야 하며, 정렬 콜론은 앞뒤에 붙어도 됩니다. 하이픈 하나짜리 결측값 행이나 더 짧은 칸은 열 단위를 설치하거나 앞 데이터 행의 수량을 지우지 못합니다.

## 답변 문맥

- 필터로 찾은 결과의 메타데이터, 후보 ID, `context_chunk_ids`는 선택한 값이 나온 청크를 가리킵니다. 개요가 다른 청크에서 오면 그 발췌 옆 본문에 파일명, 쪽 또는 섹션, 청크 ID가 나옵니다. 사업마다 기존 형식의 결과 하나를 내며, 개요의 ID는 `context_chunk_ids`에 더하지 않고 본문에 적습니다.
- 개요·기본 요청은 소개 · 목적 · 주요 업무 발췌를 우선하며, 값이 나온 청크에 소개가 있으면 그 청크도 씁니다. 제목 · 목차 · 빈 서식은 건너뛰고, 내용이 없으면 없다고 밝힙니다.
- 문맥에는 일치한 문서 수와 `값 미표기·매칭 불가로 제외` 수를, 기준 아래의 알려진 값과 따로 보고합니다. 받아들인 항목이 없는 값은 여전히 빠질 수 있고, 한 문서 안의 서로 다른 값을 의미로 맞추지는 않습니다.
- 02의 로컬 확인 셀은 API 호출 없이 값 · 항목 · 유사도를 출력합니다.
- 답변 모델은 승인된 출력 한도 8,192토큰에 추론을 포함합니다. 제공된 모든 사업을 원문 값·개요·출처가 있는 표로 나열합니다.

## 설정

| 설정 | 의미 |
| --- | --- |
| `retrieval.field_similarity` | 질문 항목명과 색인 항목명의 최소 코사인 유사도. 필요한 단위의 사용 가능한 행 중 유사도가 가장 높은 행을 문서 값으로 선택합니다. |
| `retrieval.filter_token_budget` | 일치한 전체 문서의 본문 토큰 예산. 문서마다 균등하게 나누고 선택한 값의 원문과 실제 본문 발췌를 담습니다. |

항목명 정리와 사업 문맥 보정 후 측정한 기준값은 0.66입니다. `과업비`는 약 .668, `집행한도액`은 .710, `보상한도액`은 .650이며 추정가격은 별도 정책으로 제외합니다.
숫자 없는 최대·최소와 단위 없는 배율 범위는 문서별로 가장 잘 맞는 사용 가능한 행 하나씩을 뽑아 가장 흔한 단위를 추론합니다. 같은 문서의 서식이 반복되어도 단위 집계를 늘리지 않습니다.
