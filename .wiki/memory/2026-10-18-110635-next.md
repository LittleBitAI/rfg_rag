# Design for comparing golden dataset generators A/B/C across all seven topics within a $3 budget, plus Pro workflow for C

The user asked for a design comparing golden dataset generation methods A, B and C, with metrics, a cost cap of about $3, and a procedure for generating C manually in ChatGPT Pro. The assistant proposed a paired dataset-quality comparison on shared evidence bundles, with defined metrics and a Pro packet and export format. The user chose all seven topics, an estimate before any spending, and a complete comparison. The work later ended with PR #65 merged (round 13, no remaining P2 issues). Paid runs still need the user's approval of the concrete model, call limits and whole-task estimate.

## Decisions

- Cover all seven topics in the A/B/C comparison
- Estimate the cost before spending anything; paid execution waits for the user's approval of the concrete model, call limits and whole-task estimate within $3
- Run the complete comparison through to the actual A/B/C results, including the user's Pro exports and manual quality checks

## Facts

- Method A uses topic-specific prompts, independent validation and failure-driven improvement. Method B uses a fixed prompt with the same API model and evidence. Method C is questions the user generates manually in ChatGPT Pro, imported and validated through the same pipeline (unverified)
- The earlier A pilot's five archived topic reports record 47 calls costing about $0.1114 in total (unverified)
- Proposed design: freeze one shared evidence plan of 10 bundles per topic using the existing train/validation/held-out partition; compare A's first round, B and C on the same train bundles with one question per bundle; let A run up to 3 rounds and judge its improvement on held-out data; apply the same independent validator to all methods; blind-inspect 2 outputs per method per topic by hand; keep every failure and missing output (unverified)
- Proposed metrics: usable-bundle coverage, output acceptance (auto_validated ÷ all returned outputs, including malformed ones), delivery completeness, human-confirmed quality, A's held-out improvement in percentage points, and cost per unique validated question; automated acceptance is reported separately from human-confirmed correctness (unverified)
- Proposed budget: $3 total extra API spend across A, B, C validation, retries and judging, not $3 per method; target $2.40 with a $0.60 reserve (unverified)
- The existing runner checks cost between batches of up to 8 calls and sets no output-token ceiling, so a strict cap needs bounded requests and reservation of in-flight costs (unverified)
- The previous model choice was gpt-5-mini, with low reasoning for generation and high for validation. OpenAI docs list it at $0.25/M input and $2/M output tokens but mark it deprecated (unverified)
- C's Pro output format: one JSONL row per assigned bundle with exactly bundle_id, question, answer, evidence, structure, secondary_tags. The metadata sidecar holds model_label, run_date, provided_files, tool_use, input_limits (unverified)
- C's generation tokens and cost are recorded as `unobserved`; its API validation cost can be measured; the user's handling time is recorded separately (unverified)
- PR #65 was merged at round 13 with 0 remaining P2 issues

## Preferences

- Total cost must stay within about $3
- The user wants the assistant to design the comparison method and metrics; the user then does the Pro part by chatting with GPT directly

## Open
