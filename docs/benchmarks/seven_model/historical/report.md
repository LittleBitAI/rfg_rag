# 일곱 로컬 임베딩 모델 검색 비교 결과

집계 결과와 측정 조건은 Git에 보관하고, 원시 질문·정답·근거·OCR 전사와 레코드별 내보내기는 무시된 로컬 `artifacts/`에 보관한다.

복원 출처: 기존 로컬 `artifacts/seven_model/record/report.md`. 아래 수치와 검증 기록은 당시 실행의 역사적 관측이며 이번 작업에서 재측정한 결과가 아니다.

검증 상태: 이 기록은 완료 당시 v3 소스·파일 봉인이 없는 역사적 측정이다. 사후 해시로 현재 v3 검증 통과나 추천 확정을 주장하지 않는다. 원래 추천 문장은 당시의 결론으로만 읽는다. 현재 규약은 [protocol.md](../protocol.md)를 따른다. 원시 자료와 원래 실행 protocol·manifest·split·감사·질문별 파일은 로컬 `artifacts/seven_model/record/`에 남아 있다.

이 문서는 최초 385문항 부분집합의 보존 기록이다. 전체 dev 408문항을 감사·수정하여 일곱 모델을 다시 측정한 [후속 보고서](../full_dev/report.md)가 당시의 후속 추천과 비교 결과이며, 아래 수치와 추천은 이전 실행에만 해당한다.

기존 평가 입력에 선택된 dev 부분집합에서는 KURE-v1을 우선 추천한다. Kiwi hybrid 청크 Recall@10의 수치상 선두는 Nemotron(74.46%)이고 KURE(73.37%)와 차이는 1.09%p다. 고정 가중치 비교에서 92문항 중 개선 2개·회귀 1개에 해당하는 작은 차이다. KURE는 Recall@20과 다중 근거 컨텍스트 완전성, VRAM·구축 비용에서 유리하다. Nemotron은 Recall@10을 우선하는 대안이지만 교체를 정당화하는 결정적인 승자로 판단하기 어렵다. 이 실행은 릴리스 dev 408문항 전체를 사용한 결과가 아니다.

모델·가중치·활성 색인은 바꾸지 않았다. 이 추천은 같은 dev를 나눈 validation 근거이며 최종 test 결과가 아니다. dense 단독 점수로 모델을 고르지 않았다. 아래 수치는 모두 이 PC의 실제 로컬 추론 결과이며 발행자 공개 벤치마크 수치가 아니다.

## 복구 상태와 비교 범위

컴퓨터 중단 뒤 일곱 모델의 `complete.json`, 82개 설정별 결과, 총 31,570개 문항·설정 결과와 94,710개 원시 시간 표본을 복구했다. 완료된 추론을 다시 실행하거나 원시 측정을 덮어쓰지 않았다. 각 설정은 385문항을 세 번 검색했으며, 아래 validation 시간은 194문항×3=582표본이다.

Stage 1은 KURE 고정 다섯 방법, Stage 2는 일곱 모델의 dense와 Kiwi hybrid다. 모든 방법에 isolated와 integrated가 있다. isolated는 코드 승격과 수량 우회 경로를 끄고, integrated는 운영 검색 동작을 유지한다. KURE 결과는 두 단계에서 동일 파일을 재사용했다.

전체 규약·라이선스·일차 출처·재현 명령은 비공개 로컬 `artifacts/seven_model/record/protocol.md`, 고정 revision은 [models.json](../models.json), 입력 해시는 비공개 로컬 `artifacts/seven_model/record/manifest.json`에 있다. 구성요소·문서/청크 Recall@5/10/20, MRR@5/10/20, 코드 집합, 모든 주제·분할·단일/다중 근거 값은 [quality.csv](quality.csv)에 있다. 표의 Recall·Coverage는 백분율, MRR은 0~1 값이다.

전체 dev 사용 여부를 다시 감사한 결과, 기존 평가 입력이 제외한 24개는 모두 `multi_hop`이다. `load_eval_items`와 `check_eval_items`를 릴리스 dev에 적용하면 408개 중 384개가 남고, 제외 사유 24개 모두 `핵심 사실(key_facts) 없음`이다. 이것은 정답 문자열 평가를 위한 기존 생성·평가 파이프라인의 제한이며, 검색 순위 평가에서 질문 자체를 제외할 독립적인 사유가 아니다. 이번 실행은 그 선택을 그대로 가져왔으므로 전체 dev 검색 비교로 완료했다고 해석하면 안 된다. 원본 408개는 보존되어 있지만 나머지 24개는 검색하지 않았다. 이 제외와 검색 후 청크 라벨 완전성에 따른 채점 제외는 서로 다른 단계다.

분할 seed는 `20261018`이다. 중복 질문과 공유 golden 청크·bundle 그룹을 유지했고 동결한 ID는 비공개 로컬 `artifacts/seven_model/record/split.json`에 있다. 비공개 로컬 `artifacts/seven_model/record/grouping_audit.json`에서 원본·재매핑 유효 청크의 분할 중첩이 0개임을 확인했다. 같은 문서의 다른 근거는 양쪽에 있을 수 있다. 과거 Kiwi 개발에 사용한 dev이므로 완전히 새로운 평가 자료가 아니다.

실측 385문항 모두 일반 경로다. 수량 필터의 유지와 모델별 구절 벡터 구축은 확인했지만 필터 경로의 실제 질의 품질·속도와 `0.66` 임계값의 모델 간 이전은 이 자료로 검증할 수 없다. 결과 표에는 필터 0문항을 명시했다.

## Stage 1: KURE 고정 다섯 방법

고정 hybrid 가중치는 `dense_weight=0.6`이다. 공백 BM25는 `str.split()`, 두 BM25는 `k1=1.5`·`b=0.75`다. 현행 Kiwi 규칙·사전을 그대로 유지했다. 모든 설정의 `candidate_k=50`, fusion, 기관별 교차 배치와 패킹은 동일하다.

이 validation에서는 공백 BM25가 Kiwi보다 R@10이 높았고 공백+KURE가 다섯 방법 중 높았다. 이것은 고정한 선택·라우팅·라벨 적격 집합의 결과다. 주제별 매핑 편향이 크므로 한국어 일반 검색 전체에 대한 우위로 일반화하거나 운영 토크나이저를 되돌리지 않는다.

저장한 isolated BM25 단독 순위를 전체 선택 입력에서 다시 집계하면 아래와 같다. 새 추론이나 가중치 선택 없이 기존 결과만 계산한 진단이다.

| 부분집합 | 청크 적격 | 공백 R@10 | Kiwi R@10 | 공백 우세 / Kiwi 우세 / 동률 문항 |

분할에 따라 BM25 단독의 순서가 뒤집히므로 validation의 11.41%p 차이를 일반적인 토크나이저 우열로 해석하면 안 된다. 합계 차이는 2.42%p다. 합계는 이미 본 dev의 기술 통계이며 독립 검증 결과나 새 튜닝 목표가 아니다.

선별한 3개 사례의 토큰·BM25 감사에서는 반복 토큰, 복합어 분해, 조사 차이가 순위 역전에 영향을 주는 기제를 검토했다. 문항 ID·기관/질문 설명·개별 순위·토큰별 점수·문항별 진단 결과는 비공개 로컬 `artifacts/seven_model/record/report.md`에만 보관한다. 이 공개본은 위 분할별 집계와 일반적인 해석만 제공한다. 이 감사가 공백의 일반적인 언어 이해 우위나 모든 역전의 원인을 입증하는 것은 아니다. 현재 Kiwi 규칙·사전·질문·융합은 진단 중 변경하지 않았다.

같은 그리드로 튜닝한 공백+KURE는 두 경로 모두 `0.6`을 선택하여 위 고정 행과 같다. Kiwi+KURE는 `0.8`을 선택했다. integrated의 R@10은 73.37%로 같고 R@20은 92.39%로 높아졌지만 Coverage는 72.83%로 낮아졌다. 튜닝 선택이 모든 지표의 개선을 뜻하지 않는다.

## 시간과 자원

실측 머신은 Windows 10.0.26200/WDDM, RTX 3080 10 GiB, 호스트 RAM 약 63.82 GiB, Python 3.10.11이다. PyTorch `2.11.0+cu128`, Transformers `5.19.0`, Sentence Transformers `6.1.0`, FAISS CPU `1.15.1`, Kiwi `0.24.0`이다. [runtime-freeze.txt](runtime-freeze.txt)에 전체 버전을 기록했다. 다른 프로세스를 종료하지 않았고 각 실행 전에 GPU·디스크·호스트 여유량을 기록했다.

모델은 순차 실행했다. 예열은 제외하고 단건 입력부터 반환 컨텍스트까지 GPU 동기화를 포함해 잰다. query embedding 캐시는 없다. 모델 로딩·색인 구축·지표 계산은 질의 시간에서 제외했다. 모든 설정은 세 패스에서 결과 signature가 일치했다.

## 추천의 의미와 보호 확인

Recall@10만의 수치상 선택은 Nemotron이다. 그러나 1.09%p 차이는 가까우며 KURE의 선택 R@20 92.39% 대 91.30%, 다중 full 7/9 대 6/9, CUDA allocated 1.25 대 2.64 GiB, 색인 구축 141 대 468초와 함께 판단해야 한다. 따라서 현재 자료로는 KURE를 실용적인 우선 추천으로 유지하고 Nemotron을 작은 R@10 우위를 가진 대안으로 보고한다. 통계적 유의성이나 독립 test 우위를 입증한 결과가 아니다.

Harrier·dragonkue는 KURE와 가깝지만 우선순위 지표에서 일관된 이득을 보이지 않았다. Jina는 비상업적 제한이 있고 이번 hybrid 품질·지연에서도 교체 근거가 약하다. Perplexity의 condition 이득은 numeric 회귀와 함께 봐야 한다. upskyy는 이번 품질이 낮고 라이선스도 미해결이다. 각 라이선스의 원문·호환성은 규약의 고정 일차 출처를 따른다. 상업 이용 가능성을 새로 승인하는 보고서가 아니다.

일곱 완료 기록은 모두 `network_attempts=[]`, `protected_unchanged=true`, `test_split_executed=false`다. 측정 프로세스에서 추론·telemetry 연결 시도는 없었고 API 사용량과 활성 색인의 전후 해시가 동일했다. 복구 뒤에도 동결 manifest의 보호 목록과 실제 파일을 다시 대조했다. `config.yaml`, 활성 모델·색인과 원본 평가 입력을 바꾸지 않았고 test 실행·재작성·답변·판정·OCR API 호출도 없었다. Python 프로세스 수준의 연결 가드이며 컴퓨터 전체의 다른 앱 통신까지 감사했다는 주장은 하지 않는다.

복구 검사에서 모든 저장 점수를 기존 지표 함수로 재계산하고, 모든 문항·분할 ID와 3회 시간 순서·표본 수를 확인했다. 원본 입력 9개·보호 파일 29개의 해시와 반환 컨텍스트 본문 355,639개도 대조했다. 예외·skip·xfail을 추가해 통과시키지 않았다.

변경량 약 3만 줄의 대부분은 기계 생성 집계 결과다. 현재 `.gitattributes`에는 벤치마크 파일의 `linguist-generated` 지정이 없으므로 이 속성에 따른 GitHub diff 접기를 제공하지 않는다. 공개 검토 대상은 Git에 추적된 보고서·집계 CSV·자원 요약·모델 설정·runtime 버전 목록과 실행 코드다. 모델별 raw, 동결 manifest와 split은 비공개 로컬 `artifacts/` 자료이며 PR diff에서 검토할 수 없다. 따라서 공개 집계와 실행 환경은 확인할 수 있지만 비공개 입력·분할을 이용한 provenance 대조나 원래 측정의 재실행을 공개 PR만으로 재현할 수는 없다.

최종 영향 범위 검사 명령은 규약에 적은 `tests/test_retrieval_benchmark.py`, `tests/test_retrieval_benchmark_artifacts.py`, `tests/test_ir_metrics.py`, `tests/test_retrieval.py`, `tests/test_evidence_mapping.py`의 명시적 pytest 실행이다. 결과는 `103 passed, 4 warnings in 53.43s`이며 경고 4개는 기존 RAGAS import의 deprecation이다. `python -m ruff check .`는 `All checks passed!`, `git diff --no-index CLAUDE.md AGENTS.md`는 출력 없이 종료했다. 이 다섯 테스트 파일을 정리 감사했고 현재 동작·회귀를 각각 보호하므로 삭제할 중복·폐기·불필요한 skip/xfail은 없었다.

전체 `pytest -q tests` gate는 wiki-agent 서버의 최종 검증 대상으로 남아 있으며 구현 세션에서 통과했다고 주장하지 않는다. 이 저장소는 public이지만 활성 workflow 파일이 없으므로 서버의 제한된 로컬 검증 대상이다. 구현 세션은 전체 gate나 CI dispatch를 중복 실행하지 않았다.
