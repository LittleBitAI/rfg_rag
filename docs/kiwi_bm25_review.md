# Kiwi 단어 검색 토크나이저 검토

이 문서는 Kiwi 단어 검색(BM25)에서 단어를 나누는 규칙을 바꿔 본 과거 기록입니다. 수치는 당시 로컬 기록을 옮긴 것이며, 이번에 다시 측정하지 않았습니다.

- 다섯 가지 변경을 하나씩 시험해 잡음 제거와 사전 확장 두 가지를 함께 채택했습니다.
- 두 변경을 함께 쓰면 하이브리드 청크 Recall@10이 0.747312에서 0.760753으로 1.34%p 올랐고, 다른 지표는 0.01보다 크게 떨어지지 않았습니다.
- 복합명사 결합, 하이픈 식별자, 혼합 문자 식별자는 탈락해 서비스 코드에 넣지 않았습니다.
- 채택한 사전은 `rag/retrieval/kiwi_user_words.json`이고, 지표 36개의 전체 값은 [kiwi_bm25_metrics.csv](kiwi_bm25_metrics.csv)에 있습니다.
- test 분할과 유료 API는 쓰지 않았고, API 비용은 $0입니다.

이 문서에서 단어 검색은 BM25, 의미 검색은 dense, 하이브리드는 두 점수를 합친 결과(fused)를 말합니다. 토큰은 검색할 때 쓰는 단어 조각입니다.

## 측정 조건

Kiwi 0.24.0으로 지금 규칙(기준선), 변경 다섯 가지, 채택한 조합을 로컬에서 비교했습니다. `ISMS-P` 같은 하이픈 식별자와 `GS인증` 같은 혼합 문자 식별자는 따로 시험하기로 미리 정했습니다. 실험은 임시 스크립트 `artifacts/kiwi_review.py`로 했고, 서비스 코드에 새 모듈이나 옵션을 더하지 않았습니다.

- 말뭉치는 18,989청크이고, 모든 변경에서 재작성 없이 원래 질문으로 검색했습니다.
- 임베딩 모델 KURE-v1, 의미 검색 가중치 0.6, 후보 50개, 2,500토큰, BM25 `k1=1.5`, `b=0.75`, 점수 합치기 코드는 고정했습니다.
- 기준선으로 다시 만든 토큰이 저장된 `bm25_tokens.json`과 같은지 먼저 확인했습니다.
- 문서 Recall과 MRR도 같은 문서를 합치기 전 청크 순위로 계산하고, 기관별 교차 배치를 그대로 둡니다.
- 정답 청크 표시가 없는 질문도 검색은 하지만 평균에서는 뺍니다.

### 평가 입력과 정답 청크

평가 입력 385문항 중 골든 384문항은 dev 원본(`eval/golden/dev.jsonl`)과 질문, 정답, 근거 문서, 정답 청크가 같은지 대조했고, 나머지 1문항은 `eval/eval_questions.yaml`과 대조했습니다. 평가 입력 파일의 SHA-256은 `1ffd9d3923b228c8ae130744b15447cc3468275916db5a9202ce8bb91e23f535`입니다.

처음 기준선을 재 보니 점수가 모두 0이었습니다. 평가 입력의 청크 번호는 예전 방식인데, 지금 청크 번호는 문서 해시로 만들기 때문에 서로 맞지 않았습니다. 그 점수는 버렸습니다. 대신 저장된 근거 문장이 dev의 근거 묶음과 같은지, 근거 문서가 지금 말뭉치의 같은 문서인지 확인한 뒤, 근거 문장이 같은 문서의 청크 하나에만 그대로 들어 있을 때만 그 청크를 정답으로 정했습니다. 최소 20자 같은 기존 규칙은 바꾸지 않았고, 원래 평가 입력도 덮어쓰지 않았습니다. 기준선은 질문, 말뭉치, 설정이 같으므로 저장된 검색 결과를 새 정답으로 다시 채점했습니다.

## 시험한 변경

변경은 모두 기준선에 하나씩만 적용했습니다. 차례로 쌓아 간 실험이 아닙니다.

| 변경 | 내용 |
| --- | --- |
| 복합명사 결합 | 붙어 있는 명사(NNG/NNP)를 가장 길게 이어 붙인 토큰을 더합니다. 원래 쪼갠 토큰도 남깁니다. |
| 잡음 제거 | `및`(MAG), `하`·`되`·`있`(VV), `등`·`수`(NNB)만 뺍니다. 부정어는 남깁니다. 품사까지 같을 때만 빼므로 형용사 `있`(VA)은 남고, 테스트로 이를 확인합니다. |
| 사전 확장 | 기관명 CSV에서 띄어쓰기를 없앤 이름 85개와, 말뭉치에서 붙어 나오는 명사 2~4개로 된 4~20자 단어 중 10개 이상 문서에 나온 2,620개를 합칩니다. 중복을 없앤 2,705개를 고유명사(NNP, score=1.0)로 등록합니다. |
| 하이픈 식별자 | 영문자로 시작해 하이픈으로 이어진 영문·숫자를 원문에서 찾아 소문자 토큰 하나로 더합니다(`ISMS-P`). |
| 혼합 문자 식별자 | 붙어 있는 영문과 명사를 합친 토큰을 더합니다(`GS인증`). 원래 쪼갠 토큰도 남깁니다. |

### 사전 다시 만들기

`rag/retrieval/kiwi_user_words.json`은 만든 결과를 그대로 복사한 JSON 배열(UTF-8, BOM 없음)이며, 손으로 고친 단어는 없습니다. 같은 청크와 CSV로 아래처럼 다시 만들 수 있습니다.

```powershell
$env:PYTHONPATH = (Get-Location).Path
.venv\Scripts\python artifacts/generate_kiwi_dictionary.py
```

생성 스크립트는 실험의 사전 함수를 그대로 씁니다. 채택한 뒤에도 결과가 바뀌지 않도록, 형태소 분석은 커밋 `2f746f38dba1d5fdbdfc924fbce3eac3297081b7`의 기준선 토크나이저로 고정했습니다. 기관명 CSV의 SHA-256은 `3071dc571903ec2df27c82518ed93afae692642fc204532efe5d1fc35bb4a210`입니다.

만드는 순서는 이렇습니다. 원문에서 실제로 붙어 있는 명사 묶음만 골라, 시작점마다 명사 2~4개 길이의 단어를 모읍니다. 단어가 나온 청크 수가 아니라 서로 다른 문서 수를 세고, 앞 표의 길이와 문서 수 조건을 적용합니다. 띄어쓰기를 없앤 기관명과 합친 뒤 Python 문자열 순서로 정렬하고, 들여쓰기 2칸과 마지막 줄바꿈까지 고정해 저장합니다. 마지막 확인에서 다시 만든 사전이 저장된 사전과 바이트까지 같았습니다.

## 코드 검토와 수정

### 1차: 예전 BM25 색인과 새 토크나이저가 맞지 않는 문제

예전 색인은 `개인정보처리시스템`을 `개인`, `정보`, `처리`, `시스템`으로 쪼개 저장합니다. 그런데 채택한 토크나이저는 이 질문을 한 토큰으로 만들기 때문에, 예전 색인에서 단어 검색만 하면 후보가 하나도 나오지 않았습니다. 예전 토크나이저는 같은 질문으로 청크 0을 찾았습니다. 코드를 고치기 전에 `artifacts/reproduce_kiwi_index_generation.py`로 기준선 커밋 `2f746f3`의 색인 생성 함수, 로컬 임베딩 대역, 문서 3개를 써서 재현했고, 유료 호출은 없었습니다.

고친 내용은 다음과 같습니다.

- 색인을 만들 때 `bm25_tokens.json`에 토큰과 함께 토크나이저 지문을 저장합니다. 지문은 색인 모듈 코드의 해시(줄바꿈을 맞춘 뒤), 실제로 읽은 사전의 해시, `kiwipiepy`·`kiwipiepy_model`·`hanja` 버전입니다. 모듈 전체를 해시하므로 규칙을 바꾸고 지문 버전 올리기를 잊을 일은 없지만, 주석만 바뀌어도 색인을 다시 만들라고 합니다. 지문과 토큰은 기존처럼 폴더 단위로 함께 저장되고, 저장에 실패하면 되돌립니다.
- 색인을 읽을 때(`HybridIndex.__init__`) 지문이 없거나 다르면, 의미 검색 색인과 임베딩 모델을 불러오기 전에 거부하고 `02_retrieval.ipynb`의 `build_index` 셀로 다시 만들라고 안내합니다. 오류가 난 파일에 지문만 덧붙여 다시 쓰지 않습니다.
- README도 고쳐, 처음 바꿀 때는 불러오기, 설정, 색인 만들기 셀만 실행하면 되고 유료 재작성 예제 셀은 필요 없다고 적었습니다.

같은 규칙이 적용되는 곳을 따로 셌습니다. 다른 색인 로더는 없고, 앱 다섯 곳과 문서 예제 하나 모두 같은 생성자 검사로 보호됩니다.

| 구분 | 개수 | 위치 |
| --- | ---: | --- |
| 색인 저장·읽기 | 각각 1 | `indexing._build_index`, `HybridIndex.__init__` |
| 앱에서 색인을 여는 곳 | 5 | 02 노트북 2곳, 04 노트북 1곳, 05 노트북 1곳, `frontend/server.py` 1곳 |
| 문서 실행 예제 | 1 | README의 `rerun_retrieval` 예제 |

`artifacts/verify_kiwi_round1.py`로 네트워크를 막고 실제 예전 형식 색인이 거부되는지 확인했습니다. 이어서 18,989청크를 다시 토큰화해 채택 토큰과 모두 같은지 확인한 뒤 새 형식으로 저장했습니다. 실제 `HybridIndex`에서 단어 검색만으로 같은 질문을 검색하면 후보 50개, 결과 35개가 나왔습니다. 의미 검색 색인, 수량 색인 파일 전체, 청크, 평가 입력, 규칙 파일 2개, API 사용 기록 14개는 그대로였고, 토큰과 검색 규칙도 바꾸지 않았습니다. 새 품질 측정이나 test 실행은 하지 않았습니다.

테스트는 예전 형식만 거부하던 사례를, 거부한 뒤 다시 만들고 단어 검색까지 확인하는 테스트 하나로 합쳤습니다. 코드, 사전, 패키지 버전이 바뀌면 모델을 불러오기 전에 거부하고 기존 파일을 지키는지 각각 확인합니다. 당시 전체 테스트 1,336개가 통과했고 ruff 검사도 통과했습니다.

### 2차: 예전 버전으로 되돌릴 때의 문제

1차 수정은 새 코드가 예전 색인을 읽는 경우만 막았습니다. 반대로 예전 코드가 새 색인을 읽으면 오류가 납니다. 안내를 고치기 전에 `artifacts/kiwi_round2_experiment.py`로 기준선 `2f746f3`과 수정본 `5b2773f`의 실제 코드를 각각 새 Python 프로세스에서 돌려 확인했습니다. 네트워크는 막고 임베딩은 로컬 대역을 썼으며, 청크는 `개인정보처리시스템`, `네트워크 보안`, `계약 기간` 세 개입니다.

| 상황 | 결과 |
| --- | --- |
| 예전 코드로 색인을 만들고 검색 | 말뭉치 항목과 점수 3개, 질문은 쪼갠 토큰, 단어 검색 결과 `[0]`, 하이브리드 결과 `[0, 1, 2]` |
| 새 코드가 예전 색인을 읽음 | 지문이 달라 거부, 색인 파일 5개 모두 그대로 |
| 새 코드로 다시 만들고 검색 | 항목과 점수 3개, 질문은 복합어 한 토큰, 단어 검색 결과 `[0]` |
| 예전 코드가 새 색인을 읽음 | 항목과 점수가 2개로 읽혀 검색 실패(`operands could not be broadcast together with shapes (3,) (2,) ()`) |
| 새 색인을 옆으로 옮긴 뒤 예전 색인 만들기에 실패 | 서비스 색인 자리가 비어 있고, 새로 띄운 예전 코드는 `faiss.index`를 읽지 못함. 옮겨 둔 새 색인 파일은 그대로 |
| 따로 예전 색인을 만들어 확인한 뒤 교체 | 파일 5개가 처음 만든 예전 색인과 바이트까지 같음. 새 프로세스에서 원래 토큰, 단어 검색, 하이브리드 결과가 돌아옴 |

JSON 형식만 맞추면 읽기는 되지만, 예전 질문 토크나이저와 새 말뭉치 토큰이 여전히 맞지 않습니다. 그래서 [색인 되돌리기 절차](index_rollback.md)를 만들었습니다. 색인을 읽는 프로그램을 모두 멈추고, 새 색인을 옆으로 옮기고, 되돌릴 코드와 환경으로 색인을 만들어 확인한 뒤, 확인된 폴더 전체를 비어 있는 서비스 색인 자리로 옮깁니다. 중간에 실패하면 프로그램은 멈춘 채로, 서비스 색인 자리는 빈 채로 둡니다. 이 수정에서 색인 저장, 읽기, 토크나이저 코드는 바꾸지 않았습니다.

적용 지점은 1차와 같습니다. 다른 로더는 없습니다. 색인 파일 다섯 개는 언제나 함께 옮겨야 하며, 호출하는 곳마다 따로 대체 경로나 변환을 두지 않았습니다.

`tests/test_index_migration.py`와 새 프로세스에서 도는 `tests/index_migration_worker.py`가 Git에서 실제 기준선 코드를 꺼내 지금 코드와 함께 위 과정을 확인합니다. 예전의 가상 한 방향 전환 테스트는 이 테스트에 합쳤고, 저장 실패 시 되돌리기와 코드·사전·패키지 지문 테스트는 그대로 두었습니다. 일부러 실패를 낸 뒤, 문서의 재시도 절차대로 새 임시 폴더를 쓰는지도 확인합니다.

이 확인은 Python 3.10.11, Kiwi와 모델 0.24.0, Hanja 0.15.1, rank-bm25 0.2.2, NumPy 2.2.6, FAISS 1.15.1에서 코드와 파일을 되돌려 본 것입니다. 과거의 모든 패키지 환경을 재현하거나, 실제 18,989청크 서비스 색인을 되돌리거나, 실행 중인 프로그램을 바꾸거나, 중간에 꺼져도 안전한지 확인한 것은 아닙니다. 실제로 되돌릴 때는 코드, 환경, 설정, 고정 입력을 함께 골라야 합니다. 영향받은 테스트 61개가 통과했고 ruff 검사도 통과했습니다.
