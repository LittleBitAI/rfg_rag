# 전체 dev 감사·수정 후 일곱 모델 재측정 결과

집계 결과와 측정 조건은 Git에 보관하고, 원시 질문·정답·근거·OCR 전사와 레코드별 내보내기는 무시된 로컬 `artifacts/`에 보관한다.

복원 출처: 기존 로컬 `artifacts/seven_model_full_dev/record/report.md`. 아래 수치와 검증 기록은 당시 실행의 역사적 관측이며 이번 작업에서 재측정한 결과가 아니다.

검증 상태: 이 기록은 완료 당시 v3 소스·파일 봉인이 없는 역사적 측정이다. 사후 해시로 현재 v3 검증 통과나 추천 확정을 주장하지 않는다. 원래 추천 문장은 당시의 결론으로만 읽는다. 현재 규약은 [protocol.md](../protocol.md)를 따른다. 원시 자료와 원래 실행 protocol·manifest·split·감사·질문별 파일은 로컬 `artifacts/seven_model_full_dev/record/`에 남아 있다.

Kiwi 하이브리드 청크 Recall@10을 우선하면 Nemotron-3-Embed-1B-BF16을 추천한다. validation 95문항에서 고정·선택 가중치 모두 78.42%로 가장 높았다. KURE의 고정 `0.6` 74.74%보다 3.68%p, 튜닝에서 선택한 `0.8` 71.58%보다 6.84%p 높다. 다만 Nemotron은 더 많은 VRAM과 색인 공간을 쓰고, 패킹된 근거 커버리지는 KURE보다 낮다. 작은 dev 표본에서의 추천이며 결정적인 일반 성능 우위나 도입 승인이 아니다.

운영 모델·가중치·색인·Kiwi 규칙과 사전은 변경하지 않았다. 최초 부분집합 측정은 [이전 보고서](../historical/report.md)에 보존한다. 아래는 그 점수를 재가공한 결과가 아니라 RTX 3080 10 GiB에서 일곱 모델을 다시 순차 실행한 로컬 실측이다. 발행자의 공개 벤치마크 점수와 섞지 않았다.

## 감사에서 수정한 것과 남은 한계

이전 실행은 릴리스 dev 408개 중 384개와 YAML 1개를 검색했다. `check_eval_items`가 정답 문자열 평가용 `key_facts` 없는 multi_hop 24개를 제외한 것이 원인이었다. 검색 평가 입력에서 이 조건을 제거하고 이번에는 원래 golden dev 408개 전부를 검색했다. YAML은 원본으로 보존하되 정식 golden 비교에서 제외했다.

깨진 v11 junction의 자료를 다른 패키지로 바꾸지 않았다. 원래 저장 생성 계획 11개의 bundle ID·근거 ref 전체가 정확히 일치하는 텍스트를 복구했다. 716개 ref 모두 유일하게 대응하고 원본 golden context의 완전한 `[E]` 블록과 일치한다. 이전 입력에 있던 653개 근거 텍스트도 그대로다. 원본·동결 입력 20개의 해시를 확인했다.

현재 Kiwi 토큰 저장소는 18,989청크 전부를 새로 토큰화한 결과와 같았다. 전체 408질문의 batch/단건 토큰도 같았으며, 세 사례×두 토크나이저의 독립 BM25 공식·후보 순위 검사에서 산술 오류는 발견하지 않았다. 이전 원시 순위의 Recall/MRR 6,744개 값도 독립 재계산과 일치했다. 같은 점수인 비정답 후보 두 개의 순서 차이는 기록했지만 정답 순위에 영향이 없어 운영 tie 처리를 바꾸지 않았다. 이 감사가 모든 검색 동작의 무결성을 증명하는 것은 아니다.

상세 통제·재현 명령은 비공개 로컬 `artifacts/seven_model_full_dev/record/protocol.md`, 감사 근거와 항별 점수는 비공개 로컬 `artifacts/seven_model_full_dev/record/audit.json`, 모델 ID·revision은 [models.json](../models.json)에 있다. 모델별 프롬프트·풀링·어댑터·라이선스·일차 출처는 [모델 규약](../protocol.md)을 따른다.

## 질문 수·분할·점수 분모

98문서·18,989청크와 408개 질문을 고정했다. 검색 실행 수와 채점 적격 수는 다르다. 문서 지표는 400개, 청크 지표와 Coverage는 모든 근거가 청크 라벨을 가진 194개만 채점한다. 일부 라벨 129개와 무라벨 77개를 제외하여 청크 매핑 제외율은 206/400=51.50%다. 답변 불가능 8개는 별도로 센다. 부분 근거만 골라 완전한 정답 집합으로 채점하지 않았다.

validation은 문서 적격 201개·청크 적격 95개, 튜닝은 각각 199개·99개다. 주제별 문서 수준 제외도 [exclusions.csv](exclusions.csv)에 있다. 특히 table·comparison·multi_hop 청크 매핑 제외가 커서 적격 집합이 전체 질문을 대표한다고 가정할 수 없다.

seed `20261018`로 중복 질문·공유 원본/유효 재매핑 청크·bundle을 묶은 368그룹을 유지했다. 최대 그룹은 7개다. 비공개 로컬 `artifacts/seven_model_full_dev/record/split.json`의 ID와 해시는 점수 집계 전에 동결했다. 질문·bundle·정답 청크·원본 근거 위치/텍스트의 분할 중첩은 0개지만 같은 문서의 다른 근거는 양쪽에 있을 수 있다. 이전 부분집합과 Kiwi 개발 점수를 이미 봤으므로 완전히 새로운 holdout은 아니다. validation은 이번 가중치 선택에서 제외했으며 test 결과로 부르지 않는다.

Recall은 질문별 정답 문서/청크 집합 중 상위 k 청크가 포함한 비율의 평균이다. 문서를 먼저 중복 제거하지 않는다. MRR은 상위 k의 첫 정답 청크 위치의 역수이며 다중 근거 완전성을 뜻하지 않는다. Coverage는 실제 반환 컨텍스트의 정답 청크 포함 비율, full은 전부 포함했을 때만 1이다. 단일/다중 그룹도 완전 라벨 질문만 평균낸다. 코드 membership은 순위나 k가 없는 별도 집합 지표다.

공백 hybrid는 튜닝에서도 `0.6`을 선택했다. Kiwi+KURE는 `0.8`을 선택했지만 validation R@10은 71.58%로 고정값보다 낮아졌다. R@20은 91.58%로 높아졌고 Coverage는 69.47%로 낮아졌다. validation을 보고 `0.6`으로 선택을 다시 바꾸지 않았다.

### 공백이 Kiwi보다 높은 이유에 대한 감사

전체 dev에서도 공백 BM25가 조금 높았지만 일방적인 우세는 아니다. 아래는 분리 비교이며 이미 본 dev의 기술 통계다.

| 분할 | 청크 적격 | 공백 R@10 | Kiwi R@10 | 공백 우세 / Kiwi 우세 / 동률 문항 |
| --- | ---: | ---: | ---: | ---: |
| tuning | 99 | 67.17 | 65.66 | 14 / 13 / 72 |
| validation | 95 | 73.16 | 70.00 | 14 / 11 / 70 |
| all_dev | 194 | 70.10 | 67.78 | 28 / 24 / 142 |

형태소 분석은 조사 차이를 줄이지만, BM25의 검색어별 IDF와 반복 횟수·문서 길이를 함께 바꾸므로 모든 질문의 순위가 개선되는 보장은 없다. 선별한 3개 사례의 감사에서는 반복 토큰, 복합어 분해, 조사 차이가 순위 역전에 영향을 주는 기제를 검토했다. 문항 ID·기관/질문 설명·개별 순위·토큰별 점수·문항별 진단 결과는 비공개 로컬 `artifacts/seven_model_full_dev/record/audit.json`과 원래 `report.md`에만 보관한다. 이 공개본은 위 분할별 집계와 일반적인 해석만 제공한다.

이 진단들은 알려진 세 사례의 원인 분석이며 새 정식 비교나 전체 개선율 추정이 아니다. 질문·사전·토큰 규칙을 변경하지 않았고 이 결과로 가중치를 선택하지 않았다. 발견한 입력 누락은 수정했지만, Kiwi가 반드시 이기도록 지표나 사전을 조정하지 않았다. 모든 역전의 원인을 완전히 분해했다고 주장하지 않는다.

## 추천과 검증 상태

이번 요청의 우선 기준인 Kiwi hybrid validation 청크 R@10에서는 Nemotron이 고정값과 튜닝값 모두 선두여서 우선 추천한다. 선택값 R@20도 KURE 91.58%보다 조금 높은 92.11%다. 그러나 전체 dev 선택값 R@20은 KURE 94.33%가 Nemotron 92.78%보다 높고, validation Coverage는 KURE 69.47% 대 Nemotron 68.42%, 다중 full은 7/13 대 6/13이다. 선택 p90은 약 172 대 210ms, CUDA allocated는 약 1.25 대 2.64 GiB, 전용 색인은 약 138 대 259 MiB다. 메모리·지연·컨텍스트 완전성이 더 중요하면 KURE가 합리적인 대안이다. 결과를 결정적인 단일 승자로 확대하지 않는다.

Jina는 비상업적 `CC BY-NC 4.0` 제한을 유지한다. upskyy 라이선스는 미해결로 표시한다. Nemotron의 고정 revision 라이선스는 `OpenMDW-1.1`이며 카드 metadata의 `other` 표기와 구별했다. 나머지 모델도 고정 원문과 호환성 조건을 규약에서 확인해야 한다. 이 보고서는 사용 허가를 새로 부여하지 않는다.

일곱 모델은 모두 실행 코드 commit `423d453`와 같은 소스 해시로 측정했다. 82개 설정에서 문항별 결과 33,456개·시간 표본 100,368개를 보존했다. 원본/동결 입력 20개, 보호 파일 29개, 반환 컨텍스트 본문 해시 375,175개를 대조했다. 측정 프로세스의 socket/DNS 연결 시도는 0개이며 추론·재작성·생성·판정·OCR·원격 측정 API를 호출하지 않았다. 컴퓨터 전체의 다른 앱 통신을 감사했다는 뜻은 아니다. 사용 기록·활성 색인·기본값은 그대로이며 test split은 실행하지 않았다.

가중치·매니페스트·질문 ID·원시 후보와 컨텍스트·기계 판독 요약은 원래 로컬 record 폴더에 있다. `quality.csv`는 두 단계·두 비교·세 분할·모든 요청 k·주제·그룹의 지표와 적격/제외 분모를, 비공개 로컬 `artifacts/seven_model_full_dev/record/validation_per_question.csv`는 동일 validation 질문별 값을 제공한다. 모델 채택이나 운영 색인 재구축은 수행하지 않았다.

최종 코드·테스트 상태에서 아래 영향 테스트를 실행해 `114 passed, 4 warnings in 55.90s`를 확인했다. 경고 네 개는 기존 RAGAS import deprecation이다. `ruff check .`는 `All checks passed!`, 두 에이전트 규칙 파일은 바이트 단위로 같다. 테스트 정리 감사에서 여섯 파일의 현재 동작·회귀 검사를 유지했고, 부분집합과 전체 dev의 산출물 검사는 같은 fixture로 합쳤다. 삭제할 중복·폐기 경로 테스트나 더 이상 유효하지 않은 skip/xfail은 없었다.
