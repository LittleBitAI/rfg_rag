# OCR image labelling page (1/2/3) built as a second Vite page over existing backend functions; PR #47 merged

The user asked for a frontend pipeline that shows all document images and lets a person sort each one into 1 (must be recognised), 2 (should be recognised but hard) or 3 (not needed) for OCR. The image's source document and location metadata must be kept, as in normal parsing. It had to reuse backend functions, keep folders from mixing, and leave other pipelines untouched. The user settled five scope choices: a second page in the existing Vite project, a labels file as the only output, one card per distinct image with all its locations, a read-only CRAFT badge, and labellable placeholder cards for unviewable images. The work ended with PR #47 merged (round 3, 0 remaining P2).

## Decisions

- The labelling screen is a second page in the existing React + Vite project, with a thin FastAPI server in Python. — It adds no new packages to requirements.txt or package.json, the design stays fully flexible in CSS, and the server can import backend functions directly. (rejected: Streamlit or Gradio (a new dependency and much harder to style))
- The output is a labels file only. The labels do not steer OCR in 01_preprocessing.ipynb. — Making preprocessing OCR only the images labelled 1 would mean editing preprocessing, which the user ruled out. (rejected: Wiring the labels into 01_preprocessing.ipynb)
- One card per distinct image, listing every location where that image appears.
- Show CRAFT's verdict as a badge only when artifacts/ocr_selection.jsonl exists, reading it read-only.
- Unviewable images (WMF/EMF or images that fail to decode) get a placeholder card that can still be labelled.

## Preferences

- Reuse functions already implemented in the backend as much as possible.
- The frontend must not affect other backends; it only wraps backend functionality as a shell.
- Do not build anything unnecessary. Choose the frontend language first; it should allow flexible design and depend little on other backends.
- The user's pipelines are evaluation, validation and frontend. Never touch other pipelines.
- Branches are created as feature/..., after checking how teammates named their branches.
- Plan how to keep folders from mixing.
- When images are picked, the source document's location and metadata must remain as in normal parsing.
