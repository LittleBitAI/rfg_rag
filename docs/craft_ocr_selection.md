# CRAFT 선별 기능의 구현·검증 범위

사용법은 [README의 CRAFT 안내](../README.md#craft로-ocr-전에-이미지-선별하기)를 참고합니다. 이 문서는 구현과 검증의 범위를 정리합니다.

## 유지되는 기존 기능

OpenAI Vision parser의 생성 방식, 모델 설정, 후보에 대한 응답 구조는 유지합니다. `parsing.craft.enabled` 기본값은 `false`이며 OFF이면 기존 경로입니다. 노트북의 `OCR = False`에서는 CRAFT도 실행하지 않습니다.

CRAFT는 영역 탐지에만 사용합니다. `download_enabled=False`, `recognizer=False`로 실행하며 문자 인식은 기존 Vision이 담당합니다. 새로운 OCR 모델이나 HWP/PDF 추출기를 추가하지 않았습니다.

## 상태와 저장

- `OCR_CANDIDATE`: 기존 Vision으로 전달합니다.
- `REVIEW_REQUIRED`: 자동 OCR하지 않고 출처·위치·사유를 검토 큐에 보존합니다.
- `OCR_UNNECESSARY`: 전체 픽셀이 균일한 이미지만 제외합니다.

지원되지 않는 형식, 모델 부재, 탐지 오류, 디코딩 실패는 검토 대상입니다. 낮은 탐지 점수는 자동 제외 근거가 아닙니다. 모든 판정은 캐시 폴더 옆의 `ocr_selection.jsonl`, 검토 판정은 설정한 `review_queue`에 덧붙입니다.

원본 추적은 Loader가 제공하는 정보를 보존합니다. HWP는 문서 SHA·이미지명·본문 마커 위치, PDF는 문서 SHA·페이지·이미지 번호·xref·배치 사각형입니다. HWP 바이너리 record/페이지를 새로 증명하는 기능은 아닙니다.

탐지 캐시는 raster SHA·모델 SHA·설정·EasyOCR 버전으로 구분하고 기존 OCR/승인 데이터와 분리합니다. 캐시 설정 변경은 탐지 결과에만 영향을 줍니다. Vision 응답의 새 영구 캐시를 구현한 것은 아닙니다. HWP 반복 이미지는 각 위치를 기록하고 한 번의 문서 처리에서 Vision 응답을 재사용합니다.

## 확인한 결과

최신 dev 기반 로컬 전체 테스트 453/453, 선별·연결 테스트 19개, Ruff 및 변경 형식 검사 통과를 확인했습니다. 테스트는 외부 네트워크 차단과 Vision Mock을 사용합니다. OFF 기존 객체·결과 유지, ON 후보 전달, 검토 항목 보존, 오류 처리, PDF 응답 객체 유지, HWP 반복 위치·응답 재사용을 확인했습니다.

기존 50개 실험 판정을 작은 SHA·분류 fixture로 재사용했습니다. 실제 50개 이미지를 다시 OCR하거나 새 탐지 성능을 인증한 테스트가 아닙니다. 이미지·가중치·캐시·인증 정보는 PR에 포함하지 않습니다.

## 남은 한계

의미 분류, 작은 글자·스타일 문자·체크기호의 완전 탐지, 일반 사진 분류 성능은 인증하지 않았습니다. OCR 정확도나 비용 절감 효과도 미검증입니다. 실제 운영 환경 검증과 검토 항목의 승인·반영은 별도 작업입니다. 재실행 시 JSONL 항목이 중복될 수 있습니다.

최신 `origin/dev`를 기준으로 CRAFT 관련 변경만 통합했습니다. 기존 Vision 모델·추론 설정, 사용량 콜백, 한자·목차 처리 로직은 유지합니다. PR 방향은 `feature/craft-pre-ocr-selection-clean` → `dev`입니다. 게시 직전 원격 변경 여부를 다시 확인하세요.
