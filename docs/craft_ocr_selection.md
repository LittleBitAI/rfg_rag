# CRAFT로 OCR할 그림 고르기: 만든 범위와 확인한 범위

CRAFT는 그림에서 글자가 있는 영역을 찾는 모델입니다. 이 기능을 켜면 글자가 있어 보이는 그림만 OCR로 보냅니다. 사용법은 [OCR 문서의 CRAFT 안내](ocr.md#craft로-ocr할-그림-고르기)에 있고, 이 문서에는 무엇을 만들고 무엇을 확인했는지만 적었습니다.

## 그대로 둔 것

- 기본값은 꺼짐(`parsing.craft.enabled: false`)이며, 끄면 예전과 똑같이 동작합니다. 노트북에서 `OCR = False`이면 CRAFT도 돌지 않습니다.
- OCR은 기존 OpenAI Vision이 그대로 합니다. 모델 설정과 응답 형식도 바뀌지 않았습니다.
- CRAFT는 글자 영역을 찾는 데만 씁니다. 모델을 자동으로 내려받지 않고(`download_enabled=False`), 글자를 읽는 기능도 끕니다(`recognizer=False`).
- 새 OCR 모델이나 HWP·PDF 추출기는 더하지 않았습니다.

## 그림을 나누는 방식

| 판정 | 처리 |
| --- | --- |
| OCR 대상 (`OCR_CANDIDATE`) | 기존 Vision으로 OCR합니다. |
| 사람 확인 필요 (`REVIEW_REQUIRED`) | OCR하지 않고, 어느 문서의 어느 위치인지와 이유를 확인 목록에 남깁니다. |
| OCR 불필요 (`OCR_UNNECESSARY`) | 전체가 한 가지 색으로만 된 그림만 뺍니다. |

지원하지 않는 형식, 모델 없음, 탐지 오류, 그림을 열지 못한 경우는 모두 사람 확인으로 보냅니다. 탐지 점수가 낮다고 자동으로 빼지는 않습니다. 모든 판정은 캐시 폴더 옆 `ocr_selection.jsonl`에, 사람 확인 판정은 설정한 `review_queue`에 한 줄씩 더합니다.

그림이 어디서 나왔는지는 문서를 읽는 단계에서 넘겨준 정보를 그대로 남깁니다. HWP는 문서 해시, 그림 파일 이름, 본문에서의 위치를 남기고, PDF는 문서 해시, 쪽 번호, 그림 번호, PDF 안의 그림 번호(xref), 쪽에서 그림이 놓인 위치를 남깁니다. HWP 파일 안의 쪽 번호를 새로 알아내는 기능은 없습니다.

탐지 결과는 그림 해시, 모델 해시, 설정, EasyOCR 버전별로 캐시하며, 기존 OCR 결과나 승인 기록과 섞지 않습니다. 캐시 설정을 바꿔도 탐지 결과에만 영향을 줍니다. Vision 응답을 오래 저장하는 캐시는 새로 만들지 않았습니다. HWP에서 같은 그림이 여러 번 나오면 위치는 모두 기록하고, 한 문서를 처리하는 동안에는 Vision 응답을 한 번만 받아 다시 씁니다.

## 확인한 것

처음 만들었을 때 전체 테스트 453개, CRAFT 선별과 연결 테스트 19개, ruff 검사를 모두 통과했습니다. 당시 실험한 50개 판정 결과를 다시 썼을 뿐, 실제 50개 그림을 다시 OCR하거나 탐지 성능을 새로 확인한 것은 아닙니다.

지금 테스트는 외부 네트워크를 막고 가짜 Vision 응답을 씁니다. 확인하는 내용은 다음과 같습니다.

- 끄면 예전 객체와 결과가 그대로인지
- 켜면 OCR 대상만 Vision으로 가는지
- 사람 확인 항목이 남는지
- 오류가 나면 사람 확인으로 가는지
- PDF 응답 객체가 그대로인지
- HWP에서 반복되는 그림의 위치를 모두 남기고 응답을 다시 쓰는지

판정마다 따로 만든 가짜 그림으로 시험하며, 실제 그림의 해시나 예전 분류 기록은 쓰지 않습니다. 그림, 모델 가중치, 캐시, 인증 정보는 저장소에 올리지 않습니다.

## 확인하지 않은 것

- 그림의 뜻에 따른 분류, 작은 글자·꾸민 글자·체크 표시를 빠짐없이 찾는지, 일반 사진을 잘 거르는지
- OCR 정확도와 비용이 실제로 얼마나 줄어드는지
- 실제 서비스 환경에서의 동작, 사람 확인 항목을 승인해 반영하는 과정
- 다시 실행하면 JSONL 줄이 겹칠 수 있습니다.
