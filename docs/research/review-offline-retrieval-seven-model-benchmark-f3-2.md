# 리뷰 조사 · F3, 2회차

PR #66 리뷰 4회차의 수정 전에 2026-10-19에 쓴 조사 초안입니다. 검증된 사실이나 공용 규칙이 아니며, 리뷰는 이 문서를 수정과 함께 읽습니다.

이 초안을 쓴 뒤 저장소 주인이 분명히 정했습니다. 실제 데이터셋 기록은 비공개로 두어야 하고, 측정값과 집계 통계는 공개할 수 있습니다. 아래에서 살핀 넓은 제외 규칙은 예전 규칙입니다. 결과 절은 새로 정한 요구 사항을 적용하며, 벤치마크 목표와 완료 기준은 그대로입니다.

## 문제

F3의 불변 조건은 추적되는 파일 전체에서 데이터셋 내용, 메타데이터, 거기서 나온 측정값을 빼는 것입니다. 지금 README.md:424에는 실제 dev 근거·문맥 블록의 집계와, 과거 집계에 대한 정정이 남아 있습니다. 절차 설명 안에 들어 있는 관측값도 AGENTS.md 1.4절의 예외가 아닙니다. 금지된 측정값 자체는 이 조사에 다시 인용하지 않습니다. [C1, C2]

## 실패한 수정

- 첫 수정은 ignore 규칙을 더했지만, 이미 추적되던 데이터셋에는 적용되지 않았습니다. 이어진 수정은 원래 릴리스 파일을 지우고 평가 테스트를 합성 입력으로 바꿨습니다. 필요한 조치였지만, 다른 문서에 복사된 내용까지 지웠다는 증거는 아니었습니다. 처음 수정의 귀속은 받은 리뷰 시간 순서와 1회차 기록에 근거합니다. [C3, C5, C7]

## 핵심 원리

Git 문서는 grep을 정한 패턴의 검색으로 설명하고, 작업 트리, index, tree 객체라는 검사 대상을 구별합니다. 그래서 파일 전체를 검색했다는 범위의 완전성과, 금지된 뜻을 모두 알아낸다는 판별의 완전성은 다릅니다. Presidio 공식 문서도 자동 탐지가 모든 민감 정보를 찾는다고 보장하지 않습니다. 뒤의 것은 탐지 한계의 참고 사례일 뿐이며, 이 저장소의 집계값이 개인 정보라는 근거가 아닙니다. 여기서 금지 범위를 정하는 근거는 AGENTS.md입니다. [C1, C6, C8]

## 결과

관측이며 여전히 초안입니다. 집계 문장은 README.md에서 `400f768`, `7371896`, `9063678`, `d26c9f1`, `500eae4`를 거치며 바뀌지 않고 계속 남아 있었습니다. 다시 들어온 것이 아닙니다. 수정 전 index 전체와 로컬 원본은 무시되는 `artifacts/review-round4/` 아래에 보존했습니다. 주장 검토는 보고된 숫자를 검색어로 쓰지 않고도 집계 관측을 찾아냈습니다. 그 실험 중에 저장소 주인이 공개 경계를 분명히 바꿨습니다. 그런 관측은 허용되고, 실제 데이터셋 기록은 비공개로 남습니다. 그래서 README 측정값은 남기고, F3는 지금 요구 사항에 비추어 이의를 제기했습니다. `clarified_controls.py`는 따로 짓고 손으로 분류한 대조 주장 열 개를 확인했습니다. 집계값은 쉼표, 표현, 숫자를 바꿔도 공개할 수 있고, 실제 기록은 JSONL에 있든 문장 안에 들어 있든 비공개로 남습니다. 이것은 로컬 조사 확인이지, 자동 개인 정보 보호 보장이 아닙니다. 문서 변경은 커밋 제목 `docs: clarify that aggregate measurements may be published`(기준 `500eae4`)로 알아볼 수 있고, 정확한 커밋 ID는 최종 공개 확인과 함께 적습니다. 제품 코드와 테스트는 바꾸지 않았고, 이 문서 정정을 위해 pytest를 다시 돌리지 않았습니다. 최종 스테이징·커밋 문서 검토, Ruff, 규칙 파일 바이트 일치, 공백 확인, 내보낼 객체 감사는 따로 적습니다. 기존 공개 이력은 지우지 않았고, 이 초안은 벤치마크 측정값을 따로 검증했다고 주장하지 않습니다.

공개 기록: `abeba03`이 새로 정한 공개 규칙을 구현하고, 인용한 README 측정값을 남깁니다. 로컬 대조 검토는 열 경우 모두 통과했고, 스테이징된 문서 확인은 index의 모든 파일에서 통과했으며, Ruff는 `All checks passed!`를 냈고, 규칙 파일 일치와 공백 확인도 통과했습니다. `git diff --exit-code d26c9f1 -- rag frontend tests config.yaml requirements.txt requirements-benchmark.txt`는 제품 코드, 설정, 의존성, 테스트 변경을 찾지 못했으므로, 앞선 집중 테스트 증거는 영향을 받지 않습니다. 최종 커밋 tree와 내보낼 객체 확인은 이 기록을 고친 뒤 push 전에 합니다. 이의를 제기한 이유는 집계가 없다는 주장이 아니라, 더 좁아진 저장소 주인의 지시입니다.

이어진 테스트 정리: 정리 기록을 분명히 남겨 달라는 요청에 따라, 구현 쪽은 이 작업이 바꾼 테스트 파일 아홉 개와 영향을 받는 회귀 파일 네 개를 감사했습니다. 원본·산출물 연결, 예전 형식 거부, 서로 독립인 입력 읽기, OCR 상태와 검토 동작, 노트북 설정 전달, 연결, 검색 지표 확인은 모두 지금 동작을 지킵니다. 낡은 경로, 겹치는 경우, 오래된 skip/xfail은 찾지 못해 더 지운 테스트는 없습니다. 구조 확인에서도 이 열세 파일에 똑같은 테스트 본문이나 skip/xfail 표시는 없었습니다. `bc3a16b`의 제품 코드에서 `.venv/Scripts/python -m pytest -q tests/test_local_inputs.py tests/test_eval_items.py tests/test_retrieval_benchmark.py tests/test_retrieval_benchmark_full_dev.py tests/test_retrieval_benchmark_artifacts.py tests/test_retrieval_benchmark_integrity.py tests/test_evidence_mapping.py tests/test_notebook_settings.py tests/test_ocr_selection.py tests/test_ocr_review.py tests/test_ocr_captions.py tests/test_ir_metrics.py tests/test_retrieval.py --tb=short`는 `198 passed, 4 warnings in 46.04s`를 냈습니다. 경고는 기존 RAGAS 사용 중단 경고입니다. Ruff, 공백, 규칙 파일 일치 확인도 통과했습니다. 이것은 집중 회귀 증거이지, 서버가 맡는 전체 검사나 새 GPU 벤치마크나 따로 한 리뷰가 아닙니다. 집계 공개는 계속 허용되며, F3는 저장소 주인의 정리에 따라 이의 제기 상태로 남습니다.
