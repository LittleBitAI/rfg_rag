# 질문 화면 디자인

```
누가:   RFP 를 검토하는 팀원
무엇을: 제안요청서에 대해 묻고, 답의 근거 문단을 바로 확인한다
성공:   답변의 [n] 을 누르면 답변 옆에 그 출처의 원문 청크가 열린다
```

## 배치

데스크톱 화면이다. 왼쪽 답변 열에서 읽고, 오른쪽 출처 칸에서 근거를 본다 — 근거를 보려고 스크롤하지 않는다.
사이드바(스레드 목록)는 없다 — 대화는 탭 하나에만 있다.

```
┌ RFP 질의응답 ────────────────────────────────────── 새 스레드 ┐  ← 붙는 상단 바
│ 질문 (question)                    │ 출처                      │
│                                    │ 질문 한 줄 (meta)          │
│ 답변 본문 … [1] … [2]               │ 1 파일 이름…        p.176 │  ← 두 줄 카드, 위에 고정
│ …                                  │   청크 첫머리…            │
│ ────────────────────────────────── │ ┃ [1] 파일 p.176          │  ← 펼친 청크는 목록 아래
│ 다음 턴 …                           │ ┃ 청크 본문 (표 포함)      │
│ ┌ 이어서 질문하기             ↑ ┐   │ ┃ …                       │
└─┴───────────────────────────────┴───┴───────────────────────────┘
       ↑ 답변 열 아래에 붙는 상자          ↑ 상단 바 아래에 붙고 따로 스크롤
```

- 출처를 답변 옆에 두는 이유: 처음 판(답변 위 카드 격자)은 넓은 화면의 양옆을 비워 두고 근거를 보려면 스크롤해야 해서
  "모바일 같다"는 피드백을 받았다. 옆 칸은 그 폭을 근거에 쓰고, 답변은 그대로 화면에 남는다.
- 출처 칸은 마지막 턴의 출처를 보여 주고, 이전 턴의 `[n]` 을 누르면 그 턴의 출처로 바뀐다. 칸 위의 질문 한 줄이 어느 턴인지 알려 준다.
- 카드는 두 줄(번호 · 파일 이름 · 쪽 / 청크 첫머리)로 위에 고정하고 청크는 목록 아래에 연다. 카드 바로 밑에 펼치면 긴 청크가 다른 카드를 밀어낸다.
  첫머리 줄이 있는 이유: 한 질문의 출처가 같은 파일인 경우가 많고 HWP 는 쪽 번호도 없어서 파일 이름만으로는 카드가 구별되지 않는다.
- 1024px 보다 좁으면 한 열로 접고 같은 카드 · 청크를 답변 위에 보인다.

## 글자 단계

다섯 단계(display · question · body · label · meta)만 쓰고, 한 단계가 두 가지 뜻을 갖지 않는다.
label 은 "구역 이름"과 "출처 번호"(칩) 둘 다지만 둘 다 '답변 바깥의 표지'라는 한 가지 뜻이다.
굵은 글씨와 표 머리(`strong` · `th`)는 단계가 아니라 강조로 600 을 쓴다 — 답변 안에서는 body, 청크 안에서는 meta 크기.
처음 판의 13px 단계는 "흐리고 작다"는 피드백으로 없앴다. 가장 작은 글자가 15px 이다.

## 색

글자와 바탕은 무채색이고, 강조색(청록)은 근거로 가는 길에만 쓴다 — 보내기 버튼, `[n]` 칩, 펼친 출처 카드의 테두리.
그래서 눈이 본문에서 칩으로, 칩에서 카드로 따라간다. 청록 · 파랑 · 무채색 후보 중 청록을 골랐다 (파랑은 답변 속 링크와 겹치고, 무채색은 칩이 묻힌다).
