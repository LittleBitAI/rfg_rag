# OCR

그림 속 글자는 기본으로 저장해 둔 OCR 결과를 읽어 넣으므로 API 키도 비용도 필요 없습니다(`OCR = False`).
그림을 새로 읽혀야 할 때만 `OCR = True`로 바꿔 OpenAI 비전 모델을 부릅니다. 이때 CRAFT를 켜면 글자가 있을 법한 그림만 골라 보냅니다.

## OCR 엔진 고르기

그림 종류(표 · 글 · 도식)마다, 기준 그림으로 잰 품질과 그림 한 장당 비용을 보고 엔진을 고릅니다.

- 쓸 수 있는 엔진은 OpenAI API, Gemini API(OpenAI 호환 주소), 그리고 로컬 Windows PC의 별도 환경에서 돌리는 PaddleOCR-VL-1.5입니다.
- 돈이 드는 OCR 호출은 모두 `rag/usage.py`로 비용을 기록하고, PaddleOCR는 그림 한 장에 걸린 시간을 기록합니다.
- 비교 실험의 첫 유료 호출과 전체 실행 전에는 모델별 예상 비용을 보여 주고 승인을 받습니다.
- 이번 비교에서는 표와 글은 Gemini, 도식은 GPT를 골랐고, 그림 320장의 결과를 391곳에 저장했습니다. 측정값과 비용은 [OCR 비교 보고서](ocr_benchmark.md)에 있습니다.

## `OCR = False` (기본값): 저장된 결과 읽기

01은 저장된 OCR 결과(`data/ocr_captions.jsonl`, 실제 파일은 `artifacts/local_inputs/`에 있습니다)를 읽어, 그림이 있던 자리에 `[그림/도표 설명] …` 글을 넣습니다. API 키나 호출은 필요 없습니다.

- HWP에서 본문에 자리 표시가 없는 그림은 문서 끝에, PDF 그림은 그 쪽의 본문 다음에 넣습니다.
- 기본 입력(`PREPROCESSED = None`)에서는 그림 설명도 청크로 만들어 그 자리에 넣고, 그림 앞뒤로 잘린 짧은 본문도 남깁니다.
- 저장된 결과 파일을 찾지 못하면 안내를 보여 주고 멈춥니다. 그래서 그림 설명이 모르게 빠지는 일은 없습니다. 직접 지정한 결과 파일과 `OCR = True`일 때는 파일을 자동으로 되살리지 않습니다.

## `OCR = True`: 비전 모델 부르기

`01_preprocessing.ipynb`의 `OCR = False`를 `True`로 바꾸면, 문서 속 그림을 LangChain `LLMImageBlobParser`와 고른 OpenAI 비전 모델(`OCR_MODEL`)로 글로 바꿔 청크에 넣습니다. `.env`의 `OPENAI_API_KEY`가 필요합니다.

- 이때는 저장된 결과를 읽지 않습니다.
- OCR 모델, 추론 강도, 토큰 한도의 기본값은 `config.yaml`의 `ocr` 항목에 있고, 01 설정 셀에서 바꿀 수 있습니다.
- 여러 쪽에 반복되는 그림(로고, 장식)은 청크에 넣지 않습니다. HWP는 아예 보내지 않고, PDF는 설명을 받은 뒤 반복된 설명을 뺍니다.

## CRAFT로 OCR할 그림 고르기

CRAFT는 글자를 읽는 OCR이 아니라, 글자가 있을 법한 영역을 찾는 도구입니다. CRAFT를 켜면 그림을 먼저 살펴보고, 글자가 있어 보이는 그림만 OpenAI 비전 모델에 보냅니다. 자세한 구현 범위는 [CRAFT 선별 안내](craft_ocr_selection.md)에 있습니다.

### 1. 준비

- 설치 순서대로 `python -m pip install -r requirements.txt`를 실행합니다. 선별에는 `easyocr==1.7.2`, `torch`, `pillow`를 씁니다. 글자는 OpenAI 비전 모델이 읽고, EasyOCR의 글자 인식 기능은 쓰지 않습니다.
- 미리 받아 둔 `craft_mlt_25k.pth`를 `models/easyocr/`에 둡니다. 코드가 모델을 자동으로 내려받지 않습니다. 모델 파일, 그림, 캐시는 git에 올리지 마세요.

### 2. 두 스위치

| 노트북 `OCR` | `parsing.craft.enabled` | 동작 |
|---|---|---|
| `False` | 상관없음 | 그림을 비전 모델에 보내지 않고, CRAFT도 돌리지 않습니다 |
| `True` | `false` (기본값) | 모든 그림을 비전 모델로 읽습니다 |
| `True` | `true` | CRAFT로 고른 그림만 비전 모델로 읽습니다 |

켜려면 01의 `OCR = False`를 `OCR = True`로 바꾸고, `config.yaml`의 `parsing.craft`를 아래처럼 바꿉니다. 같은 항목을 두 번 넣지 마세요.

```yaml
parsing:
  # 기존 parsing 설정은 그대로 둡니다.
  craft:
    enabled: true
    model_dir: models/easyocr
    cache_dir: artifacts/ocr_detector
    review_queue: artifacts/ocr_review.jsonl
```

끄려면 `enabled: false`로 돌려놓습니다. 코드를 바꾼 뒤에는 커널을 다시 시작하고 01을 실행하세요. `OCR = True`이면 고른 그림을 읽는 데 API 비용이 듭니다.

### 3. CRAFT를 켰을 때의 흐름

`문서 속 그림 → CRAFT로 글자 영역 찾기 → 상태 판정 → 고른 그림만 비전 모델로 읽기`

| 상태 | 뜻 | 처리 |
|---|---|---|
| `OCR_CANDIDATE` | 글자처럼 보이는 영역이 있음 | 비전 모델로 읽습니다 |
| `REVIEW_REQUIRED` | 글자가 있는지 확실하지 않거나 처리 중 오류가 남 | 읽지 않고 검토 목록에 적습니다 |
| `OCR_UNNECESSARY` | 그림 전체가 한 가지 색이라 정보가 없음 | 읽지 않습니다 |

- 글자 영역을 못 찾았거나 점수가 낮다는 이유만으로 필요 없다고 판정하지 않습니다. 표나 도식의 작은 글자를 놓칠 수 있으므로, 확실하지 않으면 검토 목록에 남깁니다.
- CRAFT를 켜면 HWP에서 반복되는 그림도 반복 횟수만으로 빼지 않습니다. 자리마다 기록하고, 같은 그림은 비전 모델의 결과를 다시 씁니다.

### 4. 검토 목록과 출처

- `artifacts/ocr_review.jsonl`을 텍스트 편집기로 엽니다. 한 줄이 그림이 나온 자리 하나이며, 상태, 이유, 원본 문서, 위치를 볼 수 있습니다. 검토를 마쳐도 이 목록이 자동으로 OCR되거나 검색에 들어가지는 않습니다.
- 모든 판정은 `artifacts/ocr_selection.jsonl`에 저장됩니다. 두 파일 모두 실행할 때마다 덧붙이므로, 다시 실행하면 같은 항목이 겹칠 수 있습니다.
- HWP는 문서 해시, 그림 이름, 본문 속 위치를 기록합니다. PDF는 문서 해시, 쪽, 그림 번호, 그림이 놓인 영역을 기록합니다.

### 5. 캐시와 오류

- CRAFT가 찾은 결과는 `artifacts/ocr_detector/`에 저장합니다. 그림, CRAFT 모델, 탐지 설정, EasyOCR 버전이 모두 같으면 다시 씁니다. 하나라도 바뀌면 다시 찾습니다.
- 탐지 설정은 `parsing.craft.settings`로 바꿀 수 있습니다. 이번 확인은 기본 설정으로만 했으므로, 설정을 바꾸면 따로 확인해야 합니다.
- 이 캐시는 비전 모델의 응답을 저장하지 않습니다. 같은 그림의 비전 모델 결과는 한 문서를 처리하는 동안에만 다시 씁니다.
- 모델 파일이 없거나, 탐지에 실패하거나, 지원하지 않는 형식이거나, 그림을 열 수 없으면 `REVIEW_REQUIRED`로 기록합니다. 그런 그림을 필요 없다고 처리하거나 몰래 비전 모델에 보내지 않습니다.

### 6. 확인한 범위와 한계

- 외부 API를 막은 시험용 데이터로, 상태마다 그림이 제대로 넘어가고 검토 항목이 보존되는지 확인했습니다. 실제 그림은 시험에 쓰지 않았습니다.
- CRAFT는 사진, 로고, 표를 구분하는 도구가 아닙니다. 작은 글자, 꾸민 글자, 체크 표시를 놓칠 수 있고, 일반 사진에서 얼마나 잘 동작하는지는 아직 확인하지 않았습니다.
- OCR 정확도가 오르거나 비용이 준다는 것을 확인한 결과는 아니며, 실제 운영 환경에서도 확인하지 않았습니다. 검토 목록을 검증된 검색 데이터로 쓰지 마세요.
