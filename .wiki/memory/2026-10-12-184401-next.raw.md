## 답 · 2026-10-12 15:27 · unverified

Langfuse Cloud is already in the second spec, and the way it's specified it doesn't grow the code or tangle the pipelines. All it adds is the `observe` decorator on the retrieval and generation entry functions, the three `LANGFUSE_*` keys in `.env`, and one package. No pipeline reads anything back from Langfuse, and without the keys the notebooks run exactly the same. Tracing therefore stays in.

One step further would add coupling: sending the four evaluation scores to Langfuse as well. To do that, generation would have to write a trace id into its answer file. Evaluation would then import Langfuse and attach each score to that id, so two pipelines would start sharing a Langfuse detail. It's small, about one function and one column, but it's the only place Langfuse would cross between pipelines. That's the question below.

The four-way evaluation split needs no new metrics, because the current config already lists the RAGAS metrics, and each one fits one category:

| Evaluation | What it judges | Metrics |
|---|---|---|
| Retrieval | Did search bring back the evidence | `context_precision`, `context_recall`, plus the existing no-cost check that the golden set's `key_facts` appear in the retrieved chunks |
| Generation | Does the answer address the question | `answer_relevancy`, plus the no-cost check that `key_facts` appear in the answer |
| Grounding | Is every claim in the answer supported by the retrieved chunks | `faithfulness` |
| End-to-End | Is the final answer correct against the reference, and what did the run cost | `factual_correctness`, latency per question, tokens and estimated cost |

All four are computed from the same single run, so no question is generated twice. One limit to know: `eval/golden_set.jsonl` (15 questions) has `reference` and `key_facts` but no evidence chunk ids. Rank metrics like Recall@k or MRR would need validation to label evidence chunks first. I left those out, since nobody asked for them.

- The guideline PR is still open. `korean-top-level-guidelines` is open as PR #1 and not merged.
- The test rule was softened on that branch. It now forbids "useless verification" (tests with no behavior to protect) rather than all test code. The branch also added a wiki-agent gate with a smoke test.

The refactor spec now follows that wording. It also updates the evaluation lines in `CLAUDE.md` and `AGENTS.md` to the four categories.
