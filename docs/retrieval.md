# 검색

질문이 들어오면 먼저 검색하기 좋은 문장으로 다듬고, 발주기관 문서로 범위를 좁힌 뒤, BM25와 임베딩 두 방식으로 찾은 결과를 합쳐 2,500토큰 안에서 답변 모델에 넘깁니다.
검색 코드(`indexing.py`)나 사전을 바꾸면 02에서 색인을 다시 만들어야 합니다.

## 질문 다듬기

02 검색 예제와 04 답변 생성은 검색하기 전에 질문을 다듬습니다(`rag/retrieval/rewrite.py`).

- 사용할 모델과 토큰 한도는 `config.yaml`의 `rewrite` 항목에서 정합니다.
- 검색과 기관 찾기에는 다듬은 질문을 쓰고, 답변 작성과 평가에는 원래 질문을 씁니다. 다듬은 질문이 비어 있으면 원래 질문으로 검색합니다.
- 04는 평가 질문을 순서대로 답하면서, 바로 앞의 질문과 답변을 최대 10개까지 다음 질문의 다듬기와 답변 작성에 함께 넘깁니다.
- 다듬기에는 앞 대화를 인용문 하나로 묶어 보냅니다. 그래야 모델이 앞 답변을 이어 쓰지 않습니다. 앞 대화는 질문을 이해하는 데만 쓰고, 사실은 지금 검색한 문서에서만 가져옵니다.
- 다듬는 규칙의 예는 아래와 같습니다.
  - 이어 묻는 질문에는 앞 대화의 기관명과 사업명을 넣습니다.
  - 비용이나 가격을 묻는 질문은 '사업예산(사업비)'로 바꿉니다.
  - 사업 전반을 묻는 질문은 '사업개요(사업명 · 사업기간 · 사업예산)'로 바꿉니다.
  - 자세히 알려 달라거나 평가해 달라는 질문은 '사업개요, 추진배경, 사업목표, 사업범위'로 바꿉니다.
- 질문마다 다듬기 API 비용이 더 듭니다. 04는 다듬은 질문과 그때 쓴 모델 · 토큰 · 비용 · 시간을 답변 파일에 따로 저장합니다.

## 두 방식으로 찾기

- 임베딩 검색과 BM25 검색에서 후보를 50개씩 뽑아 RRF로 합칩니다. RRF는 점수 대신 순위만 써서(후보마다 `1/(60 + 순위)`를 더합니다), 크기가 다른 두 점수를 억지로 섞지 않습니다.
- 02 설정 셀에서 `FUSION = "minmax"`, `DENSE_WEIGHT = 0.8`로 바꾸면 두 점수를 0~1로 맞춘 뒤 임베딩 80%, BM25 20%로 섞습니다. 7모델 비교 실험은 가중치를 바꿔 가며 재야 해서 늘 이 방식을 씁니다.
- 질문에 발주기관이 나오면 그 기관 문서 안에서만 찾습니다. 기관과 파일의 짝은 `data/data_list.csv`에서 읽습니다.
- 요구사항 번호가 정확히 맞는 조각을 먼저 담고, 거의 같은 내용은 빼고, 모두 합쳐 2,500토큰(`retrieval.token_budget`)을 넘지 않게 넘깁니다. 첫 조각은 이 한도를 넘어도 넘깁니다.
- 찾은 조각과 짝을 이루는 조각이 있으면 바로 뒤에 함께 담습니다. 같은 요구사항의 번호 · 이름 조각과 상세 내용 조각, 여러 조각으로 나뉜 같은 표가 여기에 해당합니다.
- `예산 1억원 이상인 사업`처럼 여러 사업을 수량 조건으로 고르는 질문은 별도 필터가 처리합니다. [수량 조건 검색](quantity_filter.md)을 보세요.

## 검색할 때 붙이는 머리말

검색은 조각 앞에 머리말을 붙인 글을 읽습니다. 답변 근거와 화면에는 머리말 없는 원래 글을 씁니다.

- 요구사항 머리말: 요구사항에 속한 조각에 그 요구사항의 번호나 이름이 없으면 `[요구사항 TST-901 시험 데이터 보관]`처럼 붙입니다. 번호 · 이름 조각과 상세 내용 조각이 나뉘어 있어도 상세 내용을 찾을 수 있게 하려는 것입니다.
- 절 제목 머리말: `3 | 구축범위`처럼 제목만 따로 조각이 된 문서에서는, 그 절에 속한 조각 앞에 `[구축범위]`를 붙입니다. 다음 제목이 나오거나 절 정보가 있는 조각이 나오면 멈춥니다.

## 노트북 설정과 저장 파일

- 설정 셀은 지금 실행 중인 설정만 바꾸고 `config.yaml`은 그대로 둡니다. 02는 적용한 설정을 `artifacts/retrieval_settings.jsonl`에 저장하고, 04와 질문 화면이 이 파일을 읽습니다. 색인을 다시 만들지 않을 때도 02의 설정 셀은 실행해 이 파일을 만든 뒤 04를 실행하세요.
- 모델을 바꾸면 같은 셀의 단가(`*_PRICES`, 100만 토큰당 달러)도 그 모델에 맞게 바꾸세요. 질문 다듬기와 답변의 기본 단가는 [GPT-6 LUNA 단가](https://developers.openai.com/api/docs/models/gpt-6-luna)를, 채점 단가는 [gpt-5-mini 단가](https://developers.openai.com/api/docs/models/gpt-5-mini)를 따릅니다. 설정 단가는 비용을 어림하는 값이라 실제 청구액과 다를 수 있습니다. 어림한 범위와 실제 사용량은 [수량 필터 전체 견적](quantity_filter_estimate.md)에 있습니다.
- 청크 크기를 바꾸면 01부터 다시 실행합니다. 검색 설정만 비교하려면 dev에서 [검색 전용 재실행](evaluation.md#dev-검색-전용-재실행)을 쓰면 됩니다. 새 설정으로 답변과 채점까지 보려면 04도 다시 실행합니다.

## 색인 지문과 다시 만들기

- `bm25_tokens.json`에는 토큰과 함께 지문이 저장됩니다. 지문은 `indexing.py` 코드 전체, 사전, `kiwipiepy` · `hanja` 버전 등으로 만듭니다. 그래서 `indexing.py`는 토큰 규칙과 상관없는 부분만 바꿔도 색인을 다시 만들어야 합니다.
- 지문이 없거나 지금 코드 · 사전 · 패키지와 다르면 검색이 오류를 내고 멈춥니다. 이때는 02의 불러오기 · 설정 셀과 `1. 색인 만들기`의 `build_index` 셀을 실행한 뒤 04나 질문 화면을 실행하세요. 내 PC에서만 도는 작업이라, 돈이 드는 질문 다듬기 예제 셀은 실행하지 않아도 됩니다.
- 02는 색인 파일 다섯 개(FAISS, BM25 토큰, 수량 값, 항목 이름, 항목 이름 벡터)를 옆의 임시 폴더에서 다 만든 뒤에야 제자리로 옮깁니다. 옮기다 실패하면 이전 폴더를 되돌리고, 청크 파일은 건드리지 않습니다. 다만 다른 프로그램이 색인을 읽고 있거나 중간에 꺼지는 경우까지 지켜 주지는 않습니다.
- 색인을 다시 만든 뒤 코드를 되돌리면 색인도 함께 되돌려야 합니다. [색인 되돌리기](index_rollback.md) 절차를 따르세요. 코드만 되돌리거나 새 파일에서 토큰만 꺼내 쓰는 방법은 지원하지 않습니다.

## 04가 저장하는 검색 기록

- 04는 답변마다 실제로 쓴 모델, 토큰, 비용을 저장합니다. 05는 이 저장된 비용을 쓰므로, 나중에 단가 설정을 바꿔도 지난 비용은 바뀌지 않습니다.
- 응답 시간(`latency_s`)은 질문 다듬기, 검색, 답변 작성을 합친 시간입니다. `end_to_end.csv`의 비용은 질문 다듬기와 답변 작성 비용의 합이며, 두 비용을 따로 볼 수도 있습니다. OCR과 채점 비용은 따로 셉니다.
- 검색 평가에 쓰도록, 넘기기 전의 후보 순위(합친 순위, 임베딩 · BM25 각각의 점수와 순위, 요구사항 번호 일치 여부), 답변 모델에 실제로 넘긴 조각 목록, 그때의 검색 설정을 함께 저장합니다.
- 이 기록이 없는 옛 평가 데이터나 옛 답변 파일은 04 · 05가 돈이 드는 호출을 하기 전에 거부합니다. 그때는 03 → 02 설정 셀 → 04 → 05 순서로 다시 실행하세요.
- 검색 함수 `search()`의 결과는 예전과 같습니다. `search_with_candidates()`는 같은 결과에 넘기기 전 후보 목록을 더해 돌려줍니다.
