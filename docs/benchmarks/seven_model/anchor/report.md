# 일곱 임베딩 모델 재측정 (문맥 앵커 라벨)

- 실제 서비스와 같은 하이브리드 검색에서 Nemotron이 Recall@10 78.12%로 가장 높았습니다. 지금 쓰는 KURE(73.56%)보다 4.56%p 높고, 문항별로 보면 Nemotron이 나은 문항이 24개, 못한 문항이 8개입니다.
- 대신 Nemotron은 GPU 메모리를 약 2.1배, 색인 크기를 1.9배 쓰고, 색인을 만드는 데 2.8배 오래 걸리며, p90 응답 시간이 29ms 깁니다.
- 단어 검색은 띄어쓰기로 나눈 쪽이 Kiwi 형태소 분석으로 나눈 쪽보다 나았습니다. 띄어쓰기 단어 검색과 KURE를 합친 경우가 Recall@10 80.24%로, 지금 서비스(Kiwi 단어 검색 + KURE)보다 6.68%p 높았습니다.
- 이미 여러 번 본 dev 데이터로 잰 결과라 최종 test 결과가 아니며, 모델을 바꾸자는 결정도 아닙니다. 서비스의 모델, 가중치, 색인, Kiwi 규칙과 사전은 바꾸지 않았습니다.

2026-10-19에 RTX 3080 10 GiB에서 일곱 모델을 차례로 새로 실행해 잰 값입니다. 이전 측정 점수를 다시 계산한 것이 아닙니다. 측정 방법은 [측정 규약](../protocol.md)을 따랐고, 이전 측정은 [전체 dev 재측정](../full_dev/report.md)에 있습니다.

측정할 때 커밋 `d927851`과 측정 코드 25개 파일의 해시(파일 내용을 확인하는 값)를 기록했습니다. 그 뒤 브랜치를 `origin/dev` 위로 옮기면서 커밋이 `fd997ec`로 바뀌었지만, 25개 파일의 내용은 줄바꿈 문자만 빼면 같습니다. `rag/retrieval/benchmark/common.py` 하나만 줄바꿈이 CRLF로 바뀌어 해시가 다릅니다. 일곱 모델 모두 보호 파일을 건드리지 않았고, 네트워크 연결 시도도 없었습니다.

이 문서에는 집계 수치와 측정 조건만 적었습니다. 실제 질문·정답·근거와 문항별 결과는 공유하지 않는 로컬 폴더 `artifacts/seven_model_anchor/`에만 있습니다.

## 용어

| 용어 | 뜻 |
| --- | --- |
| 의미 검색 (dense) | 문장을 숫자 벡터로 바꿔, 뜻이 가까운 청크를 찾는 검색입니다. 임베딩 모델이 이 일을 합니다. |
| 단어 검색 (BM25) | 질문에 나온 단어가 들어 있는 청크를 찾는 검색입니다. 띄어쓰기로 단어를 나누는 방식과, 형태소 분석기 Kiwi로 조사를 떼어 나누는 방식을 비교했습니다. |
| 하이브리드 검색 | 두 검색의 점수를 합칩니다. 가중치 0.6은 의미 검색 60%, 단어 검색 40%라는 뜻입니다. |
| 서비스 경로 | 실제 서비스와 똑같이 기관 필터, 요구사항 번호 우선 배치, 수량 필터, 중복 제거, 2,500토큰 담기를 모두 거칩니다. 본문 점수는 모두 이 경로입니다. |
| 실험 경로 | 요구사항 번호 우선 배치와 수량 필터를 꺼서 검색 순위만 봅니다. |
| Recall@k (R@k) | 위에서 k개 청크 안에 정답 청크가 몇 % 들었는지의 평균입니다. |
| MRR@10 | 첫 정답 청크가 몇 번째에 나왔는지를 역수로 바꾼 평균입니다. 1등이면 1, 2등이면 0.5입니다. |
| Coverage | 답변 모델에 실제로 넘어간 근거가 정답 청크를 몇 % 담았는지입니다. full은 정답 청크를 모두 담았을 때만 1로 셉니다. |
| p50 / p90 | 응답 시간의 중앙값과, 열 번 중 아홉 번이 그 안에 끝나는 시간입니다. |

## 정답 청크 표시에서 바뀐 것

이전 측정은 근거가 20자 이상이고 같은 문서의 청크 하나에만 들어 있을 때만 그 청크를 정답으로 표시했습니다. 그래서 짧은 숫자·코드·표 항목이나 여러 번 나오는 표 머리글은 표시를 받지 못해, dev 400문항 중 194문항만 청크 단위로 채점할 수 있었습니다.

이번에는 "문맥 앵커" 규칙을 더했습니다. 20자보다 짧거나 여러 청크에 들어 있는 근거는, 같은 정답 문맥의 다른 긴 근거(20자 이상)가 함께 들어 있는 청크가 딱 하나일 때 그 청크를 정답으로 봅니다. 유사도 점수는 쓰지 않습니다. 이 규칙을 기존 표시에도 적용해 보니 279개가 같은 청크를 가리켰고, 다른 청크를 가리킨 경우는 없었습니다. 기존 표시 379개는 하나도 바뀌지 않았습니다.

| 항목 | 이전 | 이번 |
| --- | ---: | ---: |
| 청크 단위로 채점한 문항 | 194 | 329 |
| 근거 일부만 표시 / 표시 없음 | 129 / 77 | 36 / 35 |
| 청크 채점에서 빠진 비율 | 51.50% | 17.75% |
| 검증 분할의 청크 채점 문항 | 95 | 162 |

근거 716개 중 600개가 정답 청크를 얻었습니다. 101개는 너무 짧아서, 13개는 후보 청크가 여럿이라 하나로 정할 수 없어서, 2개는 청크에서 찾지 못해 표시하지 못했습니다.

## 비교 방법

기본 비교는 검색 방법 다섯 개와 모델 일곱 개를 모두 가중치 0.6으로 고정하고, 청크 채점이 되는 dev 329문항 전체에서 쟀습니다. 가중치를 고르지 않으므로 dev를 나눌 필요가 없습니다. 튜닝 분할로 가중치를 고른 결과는 뒤쪽 보조 표에만 둡니다.

실험 경로는 요구사항 번호 우선 배치가 빠져 점수가 10%p 안팎 낮지만, 1단계 다섯 방법과 2단계 상위 네 모델의 순서는 서비스 경로와 같습니다. KURE와 문항별로 비교한 값은 원래 순위에서 다시 센 것이며 [all_dev_fixed.json](all_dev_fixed.json)에 있습니다. `paired_differences.csv`는 검증 분할만 셉니다.

## 해석과 한계

- 채점 문항을 194개에서 329개로 늘려도 Nemotron이 앞선다는 결과는 R@10(+4.56%p), 문항별 비교(24 대 8), 근거를 모두 담은 문항(118 대 110)에서 같은 방향이었습니다.
- 1단계에서는 띄어쓰기 단어 검색이, 2단계에서는 Nemotron이 가장 좋았습니다. 하지만 2단계는 Kiwi 하이브리드 안에서만 모델을 바꿨기 때문에, 띄어쓰기 단어 검색과 Nemotron을 합친 경우는 재지 않았습니다.
- 여러 근거 주제는 71문항 중 45문항이 아직 청크 채점에서 빠집니다.
- dev는 이전 측정, Kiwi 실험, 이전 보고서에서 이미 본 데이터입니다. 이 결과는 test 결과가 아니며 모델 도입 승인도 아닙니다.
