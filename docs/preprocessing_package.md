# 전처리 패키지 사용

전처리 담당자가 만든 청크(v11 · v12 패키지)를 받아, 다시 파싱하거나 자르지 않고 그대로 검색에 쓰는 방법입니다.
01 설정 셀의 `PREPROCESSED`에 패키지 폴더 경로를 넣고 01부터 다시 실행하면 됩니다.

## 쓰는 방법

1. 전처리 담당자에게 패키지를 받아 압축을 풉니다. `final_chunks.jsonl` · `final_elements.jsonl` · `final_records.jsonl`(또는 `chunks.jsonl` · `docs.jsonl`)이 바로 들어 있는 폴더를 `data/` 아래에 둡니다. 같은 이름의 폴더가 두 겹이면 안쪽 폴더를 씁니다.
2. 패키지와 실행 결과(`data/`, `artifacts/`)는 git에 올리지 않으므로 팀원과 VM에 따로 전달합니다.
3. `01_preprocessing.ipynb` 설정 셀에 패키지 경로를 넣습니다. 기본값 `None`이면 `data/rfp.zip`을 직접 파싱합니다.

   ```python
   PREPROCESSED = "data/RFP_Preprocessing_Final_v11_Team"
   ```

4. 01을 처음부터 실행하면 패키지의 청크와 저장된 OCR 글을 읽어 `artifacts/docs.jsonl`, `artifacts/chunks.jsonl`로 저장합니다. 파싱, OCR, 청크 나누기는 다시 하지 않습니다. 본문이 `[IMAGE]` 표시뿐인 청크는 빼고, 쪽 번호가 없는 HWP는 쪽 번호를 비워 둡니다.
5. 02부터 다시 실행해 새 색인을 만듭니다.

## 읽을 수 있는 형식

- v11 · v12 전처리 패키지(`final_chunks.jsonl` 등): 이 저장소의 청크 형식으로 바꿔 읽습니다.
- 이미 이 저장소 형식인 패키지(`chunks.jsonl` · `docs.jsonl`, 예: Golden dev 396 패키지의 `corpus/`): 그대로 읽고, `ocr_captions.jsonl`이 있으면 그림 설명 청크를 끝에 덧붙입니다.

## 가져온 것과 가져오지 않은 것

전달받은 폴더의 기능을 모두 가져온 것은 아닙니다.

| 전달받은 것 | 이 저장소에서 쓰는 범위 |
| --- | --- |
| v11 청크 | 청크 번호, 검색용 글, 답변 근거용 본문, 절 정보를 그대로 씁니다. 직접 파싱하면 청크 번호가 새로 만들어지므로 골든 데이터의 v11 번호와 맞지 않습니다. `[IMAGE]` 표시뿐인 청크 8개는 뺍니다. |
| 문서 · 레코드 정보 | 문서 이름, 제목, 쪽 번호, 문서 앞부분 글을 연결합니다. |
| 호환 패키지의 변환 코드 | 아이디어만 가져와 이 저장소의 작은 로더로 새로 짰습니다. 코드와 출력 파일은 복사하지 않았습니다. |
| 검증된 OCR 글 | 청크에 들어 있는 글을 그대로 씁니다. OCR을 다시 돌리거나, 검증하지 않은 OCR 결과를 더하지 않습니다. |
| 요구사항 · 표 연결 정보 | 요구사항 소속과 표 연결은 청크 파일로 옮겨 검색에 씁니다(요구사항 머리말, 번호 일치, 짝 조각 함께 담기). 표 칸 구조와 그림 출처 같은 자세한 정보는 넘기지 않고 원래 패키지에 남겨 둡니다. |
| 요소(Element) 단위 색인 | 쓰지 않습니다. 청크만 색인합니다. |
| 호환 패키지의 검색 코드 · 샘플 색인 · 테스트 노트북 | 참고만 했습니다. 색인은 이 저장소의 KURE 검색 코드로 새로 만들었습니다. |
| 패키지 사용 · OCR 검증 노트북과 검증 기록 | 출처 자료로 보관합니다. 다시 실행하지 않았습니다. |

## 직접 파싱한 결과와 비교하기

두 입력에 같은 평가 질문을 쓰려면 03을 한 번 실행해 `eval_set.jsonl`을 만듭니다.
정답 문서 · 청크 연결은 입력에 따라 달라지므로, 입력을 바꾸면 03을 다시 실행합니다. 골든 test는 연결 품질만 확인하고 검색 · 답변 비교에는 쓰지 않습니다.
두 입력 모두 같은 질문 파일과 02 설정으로 02 → 04 → 05를 실행하고, 네 평가 CSV를 따로 보관합니다.
