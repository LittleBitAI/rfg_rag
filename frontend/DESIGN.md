# 질문 화면 디자인

```
누가:   RFP 를 검토하는 팀원
무엇을: 제안요청서에 대해 묻고, 답의 근거 문단을 바로 확인한다
성공:   답변의 [n] 을 누르면 그 출처 카드가 열리고 원문 청크가 보인다
```

## 배치

한 줄 열(720px) 하나에 위에서 아래로 읽는다. 사이드바는 없다 — 대화는 탭 하나에만 있다.

```
첫 화면                          스레드
┌──────────────────────┐        ┌──────────────────────────┐
│                      │        │ RFP 질의응답     새 스레드 │  ← 붙는 상단 바
│  RFP 질의응답         │        ├──────────────────────────┤
│  안내 한 줄           │        │ 질문 (question)            │
│  ┌────────────────┐  │        │ 출처  [1 파일 p.3][2 …]    │  ← 답변보다 먼저
│  │ 질문 입력    ↑ │  │        │   └ 펼친 청크 본문          │
│  └────────────────┘  │        │ 답변  본문 … [1] … [2]     │
│                      │        │ ───────────────────────── │
└──────────────────────┘        │ 다음 턴 …                  │
                                │ ┌──────────────────────┐ │
                                │ │ 이어서 질문하기     ↑ │ │  ← 아래에 붙는 상자
                                └─┴──────────────────────┴─┘
```

- 출처를 답변 위에 두는 이유: 답을 읽기 전에 어떤 문서에서 왔는지가 먼저 보여야 근거를 의심하며 읽을 수 있다.
- 청크 본문은 카드 줄 아래 한 칸에만 펼친다. 카드 안에서 펼치면 격자가 흔들린다.
- `[n]` 칩은 같은 턴의 n 번 카드로 스크롤하고 그 청크를 연다.

## 글자 단계

다섯 단계(display · question · body · label · small)만 쓰고, 한 단계가 두 가지 뜻을 갖지 않는다.
label 은 "구역 이름"과 "출처 번호"(칩) 둘 다지만 둘 다 '답변 바깥의 표지'라는 한 가지 뜻이다.
